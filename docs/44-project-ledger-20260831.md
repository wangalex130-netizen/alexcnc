### 7.1 已拍板事项的落地影响

**拍板①（机身确认启动）** —— 直接影响固件与协议：

| 端 | 需要做什么 |
|---|---|
| 固件 | 收到 `{"cmd":"job","action":"prepare"}` 后只下载落盘，**不自动开始**；置 `awaitingConfirm: true`，等机身物理按钮 |
| 固件 | 物理按钮按下后才进「自检 → 加工」；`awaitingConfirm` 置回 false |
| 固件 | `{"cmd":"job","action":"start"}` 在量产形态下**可以忽略**（协议 `PROTOCOL.md:118` 已注明仅供联调模拟） |
| App | 向导最后一步改为「已发送到机器，请在机器上按开始」提示，**不做"开始雕刻"按钮** |
| App | 需要一个「已下发成功」的确认反馈（toast/提示），否则客户不知道任务有没有送到 |

> ⚠️ **新增待确认**：App 下发任务后如果立即关闭，客户如何知道任务是否成功送达？
> 建议至少在按下发时给一个明确成功提示（如「已发送到 3020 Nova，请在机器上按开始」）。

**拍板②（下载进度不展示）** —— 影响：
- App **不需要**新增 `download` 字段解析；
- 固件仍可发 `download` 字段（无害），但 App 不消费；
- 准备阶段的进度只在**机器屏幕上**展示。
