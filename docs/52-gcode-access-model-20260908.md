# CNC 刀路 / 雕刻历史的下载与访问授权模型（账号归属优先，不按客户分档）

> 文档编号：52 ｜ 日期：2026-09-08 ｜ 状态：**设计决策（待阿里云 / PC / App 三方对齐落地）**
> 关联：`docs/50-carve-history-contract-20260907.md`（雕刻历史契约）、`docs/51-bambu-history-benchmark-20260908.md`（拓竹对标）
> 触发：用户确认「卖设备不区分客户」→ 原 `docs/51` 的「B2C / 小B 分档」授权方案作废，改为「账号归属优先」统一模型。本文为 `gcodeUrl` 访问授权的权威定义。

---

## 0. 结论速览

- **授权轴从「客户类型分档」改为「数据归属」**：所有客户统一，不分 B2C / 小B / 包覆款 / Pro / Max。
- 客户对**本人账号**下的刀路 / 历史拥有完整自服务权：**重跑 + 下载 + 删除**。
- 唯一合法的「不可下载」边界是**数据来源（IP 归属）**，不是客户身份：
  - 生成的 G-code（刀路）= **客户资产** → 本人可下载；
  - 模型库源文件（我方 / 授权 IP 的 3mf / step）= **我方 IP** → 不提供文件下载，仅「发送到机器」内联调用。
- 拓竹「App 无下载入口」是其云端切片产物的生态锁定；我们给客户下载 = **数据主权 + 差异化卖点**，并顺带解决「PC 端无云端文件入口」（见 §3）。

---

## 1. 为什么不能按客户分档（决策依据）

- 用户明确：**卖设备不区分客户**。包覆款（海外 C 端）、Pro / Max（小 B 专业用户）面向不同人群，但授权模型应一致。
- 若分档（B2C 只重跑 / 小B 开放下载）会带来：账号类型判定、产品线与权限映射表、新增机型要回头改权限——持续维护债。
- 正确的授权单元应是 **数据所有权 = (accountId, deviceId)**，与「买哪款机器」无关。机器能力差异（ATC / 四轴）只影响「能生成什么刀路」，不影响「谁能访问自己的刀路」。
- 未来若做存储增值（更长保留期 / 更大空间），应是 **账号可选付费（opt-in）**，而非出厂按机型锁死——不强制分档。

## 2. 统一授权矩阵（所有客户一致）

| 操作 | 执行者 | 规则 |
|---|---|---|
| 重跑 re-run | 本人账号 | 允许；须 `gcodeExpiresAt` 未过期；CNC 安全强制材质 + 刀具复核（docs/51 R5） |
| 下载 gcode | 本人账号 | 允许（数据主权）；须 `gcodeExpiresAt` 未过期 |
| 打开源工程（PC 端） | 本人账号 | PC 本地 .3mf / CAM 工程可直接打开重编（**能力差异，非权限差异**） |
| 删除 | 本人账号 | 软删；设备绑定校验；跨账号 403 |
| 他人 / 跨账号 | — | 一律 403（账号隔离，与机型 / 客户类型无关） |

> 一句话原则：**你能动的数据 = 你自己的数据；你能下载的文件 = 你生成的刀路，不是我们的模型源文件。**

## 3. 厘清「拓竹为什么没下载入口 / PC 为什么没云端文件入口」（回答用户原疑问）

- **拓竹**：App 重打 = 重发**云端切好的 G-code**；该 G-code 是 Bambu 切片引擎的产物，Bambu 把它当自有 IP + 生态锁定，**刻意不开放下载**——所以「用户拿不到」是对的，那是锁。
- **PC 端（Bambu Studio）**：本地有 .3mf 工程可重新切片，故历史详情不放「重打」、也不需云端文件入口。
- **对 olduva 的含义**：
  1. 我们的 G-code 是**客户的资产**（App 来自其账号下载的模型 / 其自编辑；PC 来自其本地 CAM），**应当给下载**——这是信任 + 数据主权，是相对拓竹锁定的差异化竞争力。
  2. 「PC 端历史没有云端文件入口」的根因 = PC 自生成刀路若直连机器不经云，云里根本没有该文件（`docs/50` §3.6）。解法：**强制 PC 把 G-code 上传云并登记 `JobRecord`**，PC 自此拥有云端文件入口（可下载回自己的刀路），App 也能拉到 PC 发起的任务 → 跨设备统一历史（「个人工厂」体验）。
  3. 模型库源文件（我方 / 授权 IP）仍**不提供下载**，仅「发送到机器」内联调用——保护我方 IP，与客户类型无关。

## 4. gcodeUrl 生命周期（统一，不分客户）

- 落库时由云端生成预签名 `gcodeUrl` + `gcodeExpiresAt`（默认保留期，如 90 天，待阿里云确认；与拓竹 F5 对齐）。
- 过期前：重跑 / 下载均可用；过期后：历史条目保留元数据（`params` / `thumbUrl` / `modelName`），但标「已过期不可重跑」，`gcodeUrl` 失效。
- 保留期对所有客户一致；后续如需更长保留，走**账号级可选存储（付费 / 设置）**，不按机型分档。
- **`storeGcode` 隐私开关（修订 `docs/51` R4）**：改为**全用户可用的隐私选项**，不再绑定「小B」。任何用户可对自己专有 / 涉密刀路选择「仅存元数据、不存云端 G-code 文件」，保护其 IP；默认开（B2C 海外默认存，符合 `docs/51` F6 精神）。这既尊重「不区分客户」，又保留专有设计保护。

## 7. 验收标准

- [ ] 本人账号可下载自己任意一条历史 gcode（包覆款 / Pro / Max 同权）。
- [ ] 他人账号访问返回 403。
- [ ] 模型库源文件在任何端均无「下载文件」入口，仅「发送到机器」。
- [ ] PC 自生成刀路发起后，App 与 PC 历史均可见、可下载。
- [ ] `gcodeExpiresAt` 过期后，条目保留元数据、标不可重跑。
