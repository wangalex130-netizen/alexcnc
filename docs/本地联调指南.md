# 第一步（局域网）联调指南（含 D9/D10 新模型）

> 适用：嵌入式工程师不在、或手边没有真机时，用本机模拟「机器 + 模型库」，让手机 APK 在
> **局域网内**一键跑通「App 直连机器控制 + G-code 下载落盘 + 机旁确认 + 加工 + RTSP 视频」。
> 无需任何 Broker / 外网 / 云端。
> 契约总纲见 `docs/STEP1-LAN-实施设计.md`，帧格式见 `docs/PROTOCOL.md` §2、§2.4(D10)、§2.8(D9)。

## 1. 第一步要验证的闭环（D9/D10 已模拟）

```
手机 App ──TCP:8899──▶ fake_firmware --tcp（模拟 ESP32）  ← Jog/回零/开切/调平
   │  └── RTSP ──▶ 192.168.1.47:554/11（摄像头，真机才有）
   └── HTTP ──▶ server.py（模型库 + G-code 下载端点）
                    │
        D10：job prepare{gcodeUrl} → 机器 HTTP 下载落盘(download→ready)
        D9 ：job start → awaitingConfirm=true（机身屏「确认加工」）→ 物理按钮 → 自检→加工
```

## 2. 组件与端口（第一步只需两个）

| 组件 | 文件 | 端口 | 作用 |
|------|------|------|------|
| 模拟固件（TCP 模式） | `server/fake_firmware.py --tcp` | **8899** | 扮演 ESP32 TCP Server，收命令帧、回状态帧；**模拟 D10 下载落盘 + D9 机旁确认** |
| PC 伴随服务 | `server/server.py` | 8787 | 模型库 / 任务元数据 / **G-code 下载端点 `GET /api/v1/gcode/{taskId}`** |

> 第一步**不再需要 MQTT Broker**。`fake_firmware.py --tcp` 直接当机器，App 直连即可。

## 3. PC 端启动（2 条命令）

依赖：Python 3.10+。第一步 `fake_firmware` 走 TCP 模式，**无需 pip 任何库**（`job prepare`
下载用的 `urllib` 是标准库）。

```bash
# 终端 A：模拟固件（TCP Server:8899，deviceId 默认 alexcnc-001）
python server/fake_firmware.py --tcp alexcnc-001
#   ↑ 默认 --auto-confirm：awaitingConfirm 闪现 0.8s 后自动确认（联调不卡）
#   想手动验证 D9 门禁：python server/fake_firmware.py --tcp --no-auto-confirm alexcnc-001
#   此时 startJob 后停在 awaitingConfirm，需发 {"cmd":"confirm"} 才执行

# 终端 B：PC 伴随服务（模型库 + G-code 下载端点）
python server/server.py 8787
```

可选：把 G-code 指向"另一台机器"而非本机时，设环境变量：
```bash
MACHINE_HOST=192.168.1.47 MACHINE_PORT=8899 python server/server.py 8787
```

## 4. 手机 App 指向 PC（联调设置，免重新出包）

1. 装好 Real 包（构建参数 `USE_REAL_BACKEND=true`；`--dart-define=DEVICE_TCP_HOST` 留空，运行时填）。
2. App → **我的 → 联调设置**：
   - 打开「启用真实后端」
   - **TCP 主机** 填 PC 局域网 IP（如 `192.168.1.22`），端口 `8899`
   - **云端 Base URL** 填 `http://192.168.1.22:8787`（模型库；第一步仅用于取材质/任务，G-code 由它推）
   - 设备 ID 填 `alexcnc-001`（须与 fake_firmware 一致）
   - 保存并「重连」
3. 连接态显示 `已连` 即成功。

> 若想用编译期固化地址（少一步设置），出包时加：
> `--dart-define=USE_REAL_BACKEND=true --dart-define=DEVICE_TCP_HOST=192.168.1.22 --dart-define=CLOUD_BASE_URL=http://192.168.1.22:8787 --dart-define=DEVICE_ID=alexcnc-001`

## 5. 预期现象（第一步达成标准）

- 连接态 `已连`；断掉 fake_firmware 后 App 每 5s 重连，恢复后自动回连。
- 控制台 / 向导里 **Jog** 点动：状态帧 `pos` 实时变化（如 X+5 → pos.x 变 5.0）——**纯局域网直连，断外网 100% 可用**。
- 点「回零」→ 状态 `homing` 后回 `idle`，坐标归零。
- **D10 下载**：任务下发后 fake_firmware 按 `gcodeUrl` 经 HTTP 下载（日志打印行数），状态 `download:1.0 → ready`。
- **D9 确认**：点「开始雕刻」→ 状态 `ready` 且 `awaitingConfirm:true`（App 应显示「等待机旁确认」）→
  默认 auto-confirm 0.8s 后自动进入 `busy`；`--no-auto-confirm` 模式则需发 `{"cmd":"confirm"}`。
- 进入 `busy` 后先播自检 `scIndex 0→5`（App 显示「自检中 3/5」），再推进 `progress`，`rpm=12000`、`feed=600`。
- 暂停 / 继续 / 停止 状态机正确。
- 控制台 RTSP 预览（真机摄像头 `rtsp://admin:abc123456@192.168.1.47:554/11`）；无真机时该区域显示连接/出错态，不影响控制。
- 向导 Step5 调平点数按模型尺寸计算，下发 `leveling` 后 fake_firmware 打印网格方案。
- 向导 Step3 刀仓映射的定位环色点 = **防呆色**（红 `#D32F2F` / 橙 `#E65100` / 黄 `#FDD835` / 绿 `#43A047` / 蓝 `#1E88E5`），与实物刀柄环色一致。

## 6. 无手机快速自测（可选）

`fake_firmware --tcp` 自带 ticker 每秒回状态。想脚本化验证帧，可参考 `server/mqtt_loopback_test.py`
的帧内容，用任意 TCP 客户端连 8899 发 `{"cmd":"jog","axis":"x","dist":5.0}\n`，应收到状态行。

## 7. 给嵌入式工程师的对接清单（必读 `docs/PROTOCOL.md` §2）

固件侧需实现（App 已按契约对齐；`fake_firmware --tcp` 是可直接照抄的服务端骨架）：

1. ESP32 起 **AsyncTCP Server:8899**（`0.0.0.0`），单客户端串行收 JSON 行帧。
2. 解析命令帧：`jog / home / setWorkZero / spindle / aux / job(start|prepare|pause|resume|stop) / confirm / toolMap / leveling / gcode`。
3. 周期（5–10 Hz）回状态帧（同一连接），字段含 `state/pos/mpos/rpm/feed/progress/etaSec/scIndex/scTotal/download/awaitingConfirm/aux/tools`。
4. **D10 下载链路**：实现 HTTP 下载器 + SD/Flash 存储；`job prepare{gcodeUrl}` → 下载 → 广播 `download` 进度 → `ready`；`gcode` 帧同样落盘进同一执行引擎（MQTT/TCP 不传文件本体）。
5. **D9 物理确认**：`ready` 后 `job start` → 广播 `awaitingConfirm=true`；机身屏弹「确认加工」高优先级界面；**机旁物理按钮**按下后进入 `busy`（自检→加工）；未确认保持待命、不运动不起转（`confirm` 命令仅供联调模拟，量产忽略）。
6. **自检流水线由固件拥有**：进入 `busy` 后 `scTotal=5`，固件推进 `scIndex 0→5`，再进 `progress`；App 只读不计时。
7. 接收 `leveling` 帧按网格探点。
8. 摄像头接线为固定侧面机位，RTSP 地址 `rtsp://admin:abc123456@192.168.1.47:554/11`（无十字准星/加工范围叠加）。
9. **刀库颜色防呆**：刀库目录 `tool_catalog` 的 `info` 含 `color` 防呆色（2026-08-14 系统表新增），App 定位环色已精确对齐该 hex；机身屏展示刀具信息时应带同色防呆标识，与实物刀柄环色一致。

## 8. 外网联调（第二步 · MQTT）

本指南 §1–§7 是局域网（TCP:8899 直连）的第一步联调。**第二步外网联调走云 MQTT**：

- MQTT 服务器已部署：**EMQX 5.8.6 @ `43.154.192.242:8883`（TLS）**；账号 `app-demo` / `demo123`；deviceId `cnc-demo-01`；局域网真机 TCP `192.168.1.50:8899`。
- 完整指南见云端服务器侧 `cnc-control-server/docs/16-app-integration.md`（含 TLS 自签证书信任、构建参数、三步验证、推送通知状态）。
- App 侧已对齐：`_connectMqtt` 启用 `client.secure=true` + `onBadCertificate`（仅联调期，信任自签证书）；订阅 `cnc/<id>/status` + `notify`；主题/扁平 JSON 已一致。
- ⚠️ **FCM 安卓推送通知尚未做好**（云网关 `push_webhook` 仍为空），为独立待办任务（见 `docs/软件优化方向-待办清单.md` P8）。

构建示例：

```bash
flutter build apk --release \
  --dart-define=USE_REAL_BACKEND=true \
  --dart-define=MQTT_BROKER=43.154.192.242 \
  --dart-define=MQTT_PORT=8883 \
  --dart-define=MQTT_USER=app-demo \
  --dart-define=MQTT_PASS=demo123 \
  --dart-define=DEVICE_ID=cnc-demo-01 \
  --dart-define=APP_USER_ID=demo \
  --dart-define=DEVICE_TCP_HOST=192.168.1.50 \
  --dart-define=DEVICE_TCP_PORT=8899
```
