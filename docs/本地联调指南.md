# 第一步（局域网）联调指南

> 适用：嵌入式工程师不在、或手边没有真机时，用本机模拟「机器 + 模型库」，让手机 APK 在
> **局域网内**一键跑通「App 直连机器控制 + RTSP 视频」。无需任何 Broker / 外网 / 云端。
> 契约总纲见 `docs/STEP1-LAN-实施设计.md`，帧格式见 `docs/PROTOCOL.md` §2。

## 1. 第一步要验证的闭环

```
手机 App  ──TCP:8899──▶  fake_firmware --tcp（模拟 ESP32）   ← Jog/回零/开切/调平
   │  └── RTSP ──▶ 192.168.1.47:554/11（摄像头，真机才有）
   └── HTTP ──▶ server.py（模型库 + startJob 时推 G-code）
```

## 2. 组件与端口（第一步只需两个）

| 组件 | 文件 | 端口 | 作用 |
|------|------|------|------|
| 模拟固件（TCP 模式） | `server/fake_firmware.py --tcp` | **8899** | 扮演 ESP32 TCP Server，收命令帧、回状态帧 |
| PC 伴随服务 | `server/server.py` | 8787 | 模型库 / 任务元数据 / startJob 时经局域网推 G-code |

> 第一步**不再需要 MQTT Broker**。`fake_firmware.py --tcp` 直接当机器，App 直连即可。

## 3. PC 端启动（2 条命令）

依赖：Python 3.10+。第一步 `fake_firmware` 走 TCP 模式，**无需 pip 任何库**。

```bash
# 终端 A：模拟固件（TCP Server:8899，deviceId 默认 alexcnc-001）
python server/fake_firmware.py --tcp alexcnc-001

# 终端 B：PC 伴随服务（模型库 + G-code 推送）
python server/server.py 8787
```

可选：把 G-code 推给"另一台机器"而非本机时，设环境变量指向真机 IP：
```bash
MACHINE_HOST=192.168.1.47 MACHINE_PORT=8899 python server/server.py 8787
```

## 4. 手机 App 指向 PC（联调设置，免重新出包）

1. 装好 Real 包（构建参数 `USE_REAL_BACKEND=true`；`--dart-define=DEVICE_TCP_HOST` 留空，运行时填）。
2. App → **我的 → 联调设置**：
   - 打开「启用真实后端」
   - **TCP 主机** 填 PC 局域网 IP（如 `192.168.1.22`），端口 `8899`
   - **云端 Base URL** 填 `http://192.168.1.22:8787`（模型库；第一步仅用于取材质/任务，G-code 由它推）
   - 设备 ID 填 `alexcnc-001`（须与 fake_firmware 一致）
   - 保存并「重连」
3. 连接态显示 `已连` 即成功。

> 若想用编译期固化地址（少一步设置），出包时加：
> `--dart-define=USE_REAL_BACKEND=true --dart-define=DEVICE_TCP_HOST=192.168.1.22 --dart-define=CLOUD_BASE_URL=http://192.168.1.22:8787 --dart-define=DEVICE_ID=alexcnc-001`

## 5. 预期现象（第一步达成标准）

- 连接态 `已连`；断掉 fake_firmware 后 App 每 5s 重连，恢复后自动回连。
- 控制台 / 向导里 **Jog** 点动：状态帧 `pos` 实时变化（如 X+5 → pos.x 变 5.0）。
- 点「回零」→ 状态 `homing` 后回 `idle`，坐标归零。
- 点「开始雕刻」→ 状态 `busy`，先播自检 `scIndex 0→8`（App 显示「自检中 3/8」），再推进 `progress`，`rpm=12000`、`feed=600`。
- 暂停 / 继续 / 停止 状态机正确。
- 控制台 RTSP 预览（真机摄像头 `rtsp://admin:abc123456@192.168.1.47:554/11`）；无真机时该区域显示连接/出错态，不影响控制。
- 向导 Step5 调平点数按模型尺寸计算，下发 `leveling` 后 fake_firmware 打印网格方案。

## 6. 无手机快速自测（可选）

`fake_firmware --tcp` 自带 ticker 每秒回状态。想脚本化验证帧，可参考 `server/mqtt_loopback_test.py`
的帧内容，用任意 TCP 客户端连 8899 发 `{"cmd":"jog","axis":"x","dist":5.0}\n`，应收到状态行。

## 7. 给嵌入式工程师的对接清单（必读 `docs/PROTOCOL.md` §2）

固件侧需实现（App 已按契约对齐）：

1. ESP32 起 **AsyncTCP Server:8899**（`0.0.0.0`），单客户端串行收 JSON 行帧。
2. 解析命令帧：`jog / home / setWorkZero / spindle / aux / job(start|pause|resume|stop) / toolMap / leveling / gcode`。
3. 周期（5–10 Hz）回状态帧（同一连接），字段含 `state/pos/mpos/rpm/feed/progress/etaSec/scIndex/scTotal/aux/tools`。
4. **自检流水线由固件拥有**：`job start` 后 `scTotal=8`，固件推进 `scIndex 0→8`，再进 `progress`；App 只读不计时。
5. 接收 `gcode` 帧并缓冲，`job start` 执行之（第一步 G-code 由 `server.py` 经局域网推）。
6. 接收 `leveling` 帧按网格探点。
7. 摄像头接线为固定侧面机位，RTSP 地址 `rtsp://admin:abc123456@192.168.1.47:554/11`（无十字准星/加工范围叠加）。

参考实现：`server/fake_firmware.py --tcp`（服务端骨架可直接照抄）。
