## 0. 结论速览（先读这段）

1. **「机器终端（机身屏）」是系统核心**：ESP32 是状态唯一真值源（SSOT），机身屏是机器侧
   唯一的本地人机界面；App 与电脑端都是它的**远程镜像与扩展**。
2. **双云端职责**：
   - **视频推流服务器①**：接收机器/摄像头推流（RTMP/WebRTC），向外网三端分发（HLS/WebRTC）；
     内网时三端直连 RTSP，不经过它。
   - **状态控制+模型库服务器②**：设备注册/在线、状态汇聚、命令转发（外网）、模型/G-code 库、
     任务元数据、材质参数主表、账户与历史、诊断。**它是三端同步的中枢**。
3. **App ↔ 电脑端不直连**；二者统一经②同步（模型库/任务/历史/材质），内网控制与视频各自直连机器。
4. **配网只在机器端**：手机端与电脑端**不需要配网功能**；配网（AP + 机器唯一码）由机身屏承担。
5. **调平算法两端一致**：机器端固件与电脑端 ArtiMaker 的调平算法**完全一致**（同一算法/参数）。
6. **鉴权以机器唯一码为准**：每台机器有唯一码，App/电脑端按唯一码确认这台机器；外网 MQTT 加 Token/证书。
7. **机身屏无"确认类"输入**：远程任务、调平参数等下发后**机器直接开始动作**，机身屏只显示，不确认。
8. **落地顺序**：内网直连闭环（第一步）→ 外网 MQTT+视频推流（第二步）→ 三端深度同步（第三步）。

| D2 | 调平算法一致性 | **机器端与电脑端调平算法完全一致**（同一算法，双端各自实现） |

## 2. 三终端定位与职责

| 端 | 角色定位 | 核心职责 | 真值源依赖 |
|----|---------|---------|-----------|
| **机身屏（机器终端）** | **系统核心 / 机器侧 HMI** | 实时显示状态/坐标/进度/报警；**配网（AP + 唯一码）**；基础控制（暂停/急停/回零）；断网兜底。**无确认类输入，任务/调平参数下发即执行** | ESP32（同机共享，不走网络） |
| **手机 App（alexcnc）** | 移动控制端 / 移动监控端 | 模型库浏览→向导 6 步→控制；实时监控（状态+RTSP+2D 刀路）；远程监视（外网）；**设备发现与选择（按唯一码，不做配网）** | 状态来自 ESP32/服务器，本地只渲染 |
| **电脑端（ArtiMaker）** | 设计/切片工作站 + 控制端 | 🎨设计（资源库/AI/2D·2.5D）→ ⚙️生成（一键刀路/3D 预览）→ 🔨制作（控制/GRBL 兼容）；**调平算法与机器端完全一致**；不做配网 | 切片与设计本地完成；控制与状态来自机器 |

> **为什么机身屏是核心**：即使 App/电脑端全部离线，机器仍能独立运行——自检、加工、报警、
> 急停都由 ESP32 本地闭环；机身屏是这台"本地闭环"的人机出口（含配网与唯一码展示）。三端只是对同一真值的不同镜像。

## 3. 双云端服务器职责

### ① 视频推流服务器（媒体面）
| 能力 | 说明 |
|------|------|
| 收流 | 机器端把 RTSP 转推上来（RTMP / WebRTC / SRT） |
| 分发 | 外网三端经 HLS（低延迟档）/ WebRTC（实时档）观看；内网不经过它（直连 RTSP） |
| 地址注册 | 推流地址/播放地址上报给②，由②分发给各端 |
| 录播（可选 P2） | 延时摄影、加工回放存档 |

### ② 状态控制 + 模型库服务器（业务面，三端同步中枢）
| 域 | 能力 |
|----|------|
| 设备 | 注册/认证（**机器唯一码** + Token/证书）、在线状态、固件版本 |
| 状态 | 汇聚机器 statusStream（外网中转给三端）、报警告警推送 |
| 命令 | 外网控制转发（App/电脑端 → 机器），限权（监视模式锁 Jog/开切） |
| 模型库 | 灵感库（公开）、我的空间、历史记录；模型/图纸资产 |
| 任务/G-code | 切片服务、TaskMetadata（尺寸/材质/刀具）、**G-code 直推机器**（App/电脑端不持有） |
| 材质 | 材质参数主表（rpm/feed/plunge/刀具），三端共用 + 本地缓存 |
| 账户 | 登录/注册、**设备绑定（一账号多机，按唯一码）**、跨端会话 |
| 诊断 | 日志上报、远程排障 |

> **②与①的交互**：机器推流成功后把「播放地址」上报② → ②把地址写入设备详情 → 三端从②
> 拉取播放地址后连①观看。①本身不存业务数据。

## 6. 内网 / 外网 边界细则

| 维度 | 内网（同 Wi-Fi） | 外网（4G/异地） |
|------|----------------|----------------|
| 控制 | 直连机器 TCP:8899，低延迟全功能（Jog/回零/开切） | 经② MQTT 转发，**监视模式**（锁 Jog/开切，仅监控+暂停/停止） |
| 状态 | 直连订阅 5–10Hz | 经② 汇聚 1–5Hz |
| 视频 | 直连 RTSP（200–500ms 延迟） | 经① WebRTC/HLS |
| 模型库/任务/材质/账号 | 经②（方案 A，云端中枢） | 经② |
| G-code | ②/局域网服务 直推机器 | ② 直推机器 |
| 断外网 | 控制+状态+RTSP 完整可用（模型库/任务同步不可用，方案 A 限制） | 不可用（依赖云端） |
| 判定/鉴权 | 按**机器唯一码**匹配本机（mDNS/手动 IP 发现） | 唯一码 + Token/证书登录② |

> **切换逻辑**：App/电脑端启动 → 按唯一码发现/选择机器 → 内网直连（全功能）或走②（监视模式）。

## 7. 内网「电脑端 / App 同步」专项

### 7.1 需要同步什么

| 数据 | 真值源 | 流向 | 何时同步 |
|------|--------|------|---------|
| 模型/任务（电脑端设计产物） | 电脑端（ArtiMaker）→② | 电脑端→②→App 图库 | 电脑端生成时上传；App 拉取（启动/下拉刷新/推送） |
| 任务元数据（尺寸/材质/刀具/预览矢量） | ②（切片后回填） | ②→三端 | 任务就绪时 |
| G-code | ②/局域网服务 | **直推机器**，三端不持有 | startJob 前 |
| 材质参数/刀库 | ②（主表） | ②→三端缓存 | 启动 + 打开页面静默刷新 |
| 历史记录/我的空间 | ② | ②→App/电脑端 | 进入页面/刷新 |
| 机器状态 | ESP32 | 各自直连（内网）或经②（外网） | 实时 |

### 7.2 同步方案（✅ 已定：方案 A）

| 方案 | 做法 | 状态 |
|------|------|------|
| **A 纯云端中枢（已定，起步）** | 电脑端/App 全部经②同步；内网控制仍直连机器 | ✅ **按 A 先开始** |
| B 局域网伴随服务 | 内网多跑一个 `server.py` 类服务 | 暂缓（断网增强，后续评估） |
| C 混合 | 内网优先局域网服务，外网走② | 后续评估 |

### 7.3 明确"不直连"的交互（避免重复建设）

- App 与电脑端**不做点对点文件传输**：模型/G-code 要么经②、要么经局域网服务，单一来源。
- 三端**不做状态互转**：都订阅 ESP32 同一真值，谁在线谁显示，不互相代传。
