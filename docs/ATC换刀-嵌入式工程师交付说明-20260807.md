## §1 安全红线（最高优先级，固件内置，不依赖上位机）

> 原则：**"执行换刀不再做刀具检测"只免除刀具种类识别；仓位限位校验（有刀/无刀）必须每次换刀都做，且由固件在动作内部强制执行**——上位机断连/App 被杀不影响安全。

1. **放刀动作下探前**：实时读取目标槽位 LIMIT 传感器。
   - 该槽登记为"空"但 **LIMIT==1（实际有刀）→ 立即 E-STOP（急停+报警），绝不继续下探放刀**（防砸刀/撞刀）。
2. **取刀动作前**：实时读取目标槽位 LIMIT。
   - 该槽登记为"有刀"但 **LIMIT==0（实际无刀）→ 报警/暂停，提示用户确认**（刀可能被取走）。
3. 上述检查**内置在放刀/取刀动作序列里**（固件闭环），不是上位机流程步骤。

## §2 指令集（照此实现：原 11 条 + 修正 2 条 + 新增 2 条）

| 指令 | 功能 | 回复 | 变更 |
|------|------|------|------|
| `$KNIFE_INFO` | 查询刀库全部（CURRENT/SLOT：刀号+坐标+LIMIT） | `[KNIFE:CURRENT=6][KNIFE:SLOT1=#5,X=800,Y=500,LIMIT=1]...` | 原样 |
| `$KNIFE_GET=T1` | 查询单个刀仓（含 LIMIT 物理限位） | `[KNIFE:SLOT1=#5,X=800,Y=500,LIMIT=0]` | 原样；**LIMIT 语义：0=无刀 / 1=有刀** |
| `$KNIFE_SET=T1:#5` | 登记仓位刀具编号 | `[KNIFE:SET=T1:#5]` / `[ERROR,SET=T1:#6]` | **#0 = 清空仓位**（显式支持 `$KNIFE_SET=T1:#0`） |
| `$KNIFE_COVER=T1:#5` | 强制覆盖仓位登记（仓位显示有刀时） | `[KNIFE:COVER=T1:#5]` | 原样 |
| `$KNIFE_SAVE_POS=T1:X800Y500Z-15` | 保存刀仓坐标 | `[KNIFE:OK]` / `[ERROR:XY,EXC]` | **由 SAVE_XY 升级：XY 必须，Z 可选**（若 Z 下探高度固件写死，则 Z 可不传） |
| `$KNIFE_NEW=#6` | 登记当前主轴刀具编号（手动装刀确认） | `[KNIFE:NEW=#6]` | 原样 |
| `$KNIFE_REPL=T2` | **换刀（参数 = 槽位 T1-T4）**：主轴有刀先放后取、无刀直接取；末尾自动对刀 | `[KNIFE:REPL=T2:#5]` / `[ERROR:REPL=T2:#0]`（槽位无刀） | **参数语义修正：按槽位，不再用 # 刀具号**（消除歧义） |
| `$KNIFE_RELEASE` | 放刀：当前主轴刀具放回相应刀仓 | `[KNIFE:OK]` / `[ERROR:RELEASE]` | 原样 |
| `$KNIFE_PROBE` | **自动对刀（Z-Probe 取刀长偏移）**；换刀序列末尾由固件自动执行，也可单独调用 | `[KNIFE:OK,OFFSET=Z-0.32]` | **新增** |
| `$KNIFE_SETTER=X100Y10Z-50` | **配置对刀块绝对坐标**（可扩展探针偏移/触发高度字段） | `[KNIFE:OK]` | **新增** |
| `$KNIFE_STATUS` | 查询换刀状态 | `[KNIFE:IDLE,CURRENT=#6]` / `[KNIFE:RUNNING,TARGET=#2]` / `[ERROR:STATUS]` | 原样 |
| `$KNIFE_ABORT` | 中止换刀 | `[KNIFE:OK]` | 原样 |

> 约定：**T=刀仓编号 1~4；#=刀具编号（全局统一，#0=空仓）**。换刀统一按槽位（T），上位机负责"逻辑刀号→槽位"寻址。

## §3 换刀状态机（固件实现参考）

```
                 ┌─ ① 限位自检：放刀位应"空"？取刀位(T2)应"有刀"？任一异常 → E-STOP / alarm
$KNIFE_REPL=T2 ─▶ ├─ ② 放旧刀：读当前刀坐标 → 下探 → 放 → LIMIT 确认
   (idle)        ├─ ③ 取新刀：读 T2 坐标 → 下探 → 取 → LIMIT 确认
                 ├─ ④ 自动对刀：$KNIFE_PROBE（移对刀块 → 下探 → 记 Z 偏移）
                 ├─ ⑤ 更新 CURRENT/仓位存储
                 └─ 完成 → idle（回复 REPL 成功）
                 任一失败 → alarm（广播失败步，见 §4）
```

- 全程 `$KNIFE_STATUS` 可查：`IDLE` / `RUNNING,TARGET=T2` / `ERROR`。
- `$KNIFE_ABORT` 随时可中止：固件停在**安全位**（主轴抬起、回刀库上方），并保持状态可查询。

## §4 换刀失败 / 中止的定义（需固化）

| 情形 | 行为 |
|------|------|
| 失败（限位/放刀/取刀/对刀任一异常） | 固件 → `alarm` + 广播**失败步**（`REPL:T2 FAIL@STEP=放刀|取刀|对刀|限位`）→ 三端弹窗 |
| 用户中止（$KNIFE_ABORT） | 停在安全位，状态回 `idle`，CURRENT 保持中止前记录 |
| 恢复路径 | 人工干预（手动放回/取出）→ 重新登记（`$KNIFE_NEW` / `$KNIFE_SET`）→ 重发 REPL 或放弃任务 |

## §5 需要你确认/提供的硬件参数（阻塞 ATC 固件化，请尽快）

1. **刀仓坐标**：4 仓位 X/Y + 放刀/取刀**下探高度与安全高度 Z**（决定 SAVE_POS 的 Z 是否必须）；
2. **对刀块**：绝对坐标 X/Y/Z + **探针偏移 / 触发高度**（决定 SETTER 字段）;
3. **LIMIT 传感器**：4 仓位限位开关布局、信号定义（触发=1？常闭？）；
4. **刀具编号表**：`#编号 ↔ 型号/直径/类型`（如 #1=1/8V 刀、#2=1/16 铣刀）——**全局统一，三端+云端共用**，请产品+嵌入式共同敲定；
5. **夹爪/机械动作**：夹爪松开-夹紧时序、Z 下探安全余量（防夹刀柄公差）。

## §6 与现有架构的衔接（了解即可，无需改动）

- `$KNIFE_*` 是**下位机指令集**；App/电脑端用 JSON 帧包装同一语义（`{"cmd":"atc",...}`），后续并入 PROTOCOL.md；
- **换刀触发两种模式共用同一 REPL 逻辑**：
  - A 固件自主（路径二：G-code 落盘本地执行，固件解析换刀 M 代码内部触发 REPL）——**推荐/默认**；
  - B 上位机主导（路径一：网页/网关分段下发，上位机在换刀点发 REPL）。
  - 你只需实现 REPL 指令逻辑本身，**不区分来源**。
