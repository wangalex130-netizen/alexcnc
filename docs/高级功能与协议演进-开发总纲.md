## 0. 演进一句话

> v2.1 时代：**电脑端上位机主导一切**（切 G-code、插换刀/对刀指令、软件重写 Z 补偿、软件存续雕快照），
> 用 `LY_` 二进制帧走 USB/WiFi 直连机器，**没有 App、没有云端、没有机身屏**。
>
> 现在：高级功能（ATC 换刀/对刀、自动调平、断电续雕）**正逐步下放进下位机固件**（方案 A → 方案 B）；
> 交互升级为三端双云；协议升级为**换行分隔 JSON 帧**（局域网 TCP:8899 直连 / 外网 MQTT），
> 与旧 `LY_` 帧**不再共用**（电脑端旧驱动协议退役，新电脑端按新 JSON 对接）。

## 1. v2.1 → 现在的架构差异

| 维度 | v2.1（2026-04） | 现在（2026-08 起） |
|------|----------------|-------------------|

## 2. 高级功能全景与归属（谁执行 / 谁发意图 / 谁展示）

> 铁律（沿用并强化）：**凡是涉及刀具、主轴、三轴运动、探针接触的序列，一律由固件拥有并执行**；
> App/电脑端只发**高级意图**（如 `atc start`、`leveling`、`saveState`），然后**监听固件广播**。
> 理由：安全闭环必须在 MCU 内完成（网络抖动/App 被杀不能影响换刀/对刀/调平过程）。

### 2.1 自动换刀 + 自动对刀联动（ATC & Auto Z-Probing）

| 项 | 归属 | 说明 |
|----|------|------|
| 刀库初始化/刀具绑定 | 三端 UI（App 设置 / 电脑端刀具管理）+ 固件存储 | 出厂 4 刀位默认：1/8"铣刀、1/16"铣刀、1/8"球头、1/8"30°V；用户可改绑（`updateToolMap`） |
| ATC 序列（开/合盖、抓刀/放刀、换刀） | **固件**（方案 B，迁移中） | 旧方案 A 是上位机插绝对坐标指令——**易撞机，淘汰** |
| 自动对刀（探针下压取 Z 偏移） | **固件** | 对刀块 XY/高度、探针偏移/触发高度由固件配置（待嵌入式提供参数） |
| 半自动换刀（手动装/卸刀） | 固件执行 + 三端 UI 引导 | 用户选刀位→装/卸→固件执行动作→**用户确认到位**（无自动检测前） |
| 粗雕→精雕自动衔接 | **固件**（startJob 后内部状态机） | 工序顺序由模型固定，固件按序换刀；App 只发 startJob |
| 失败检测 | 待定 | 抓刀/放刀失败、探针失败、刀长超限：**需硬件方案**（见 §7） |

> **约束保留**：ATC 流程中**不支持断电续雕/脱机雕刻同时进行**（v2.1 原约束）。

### 2.2 自动调平（Auto Bed Leveling / Height Mapping）

| 项 | 归属 | 说明 |
|----|------|------|
| 调平参数（范围=材料尺寸、类型=平面/网格、间距 10/20/50mm） | App/电脑端 UI → `setLevelingPlan(mode,cols,rows)` | 网格点数由**云端下发的真实模型尺寸**计算（已落地 App） |
| 执行网格探测 | **固件** | 逐点下探针，广播进度；异常点上报，**无自动处理，需用户介入**（v2.1 同） |
| 补偿方式 | **双路径并存，唯一补偿方（二选一）**（2026-08-07 确认，见下） | 路径一 host 补偿 / 路径二 firmware 补偿 |
| 补偿矩阵展示 | 三端（App 调平页 / 电脑端 / 机身屏可选） | 云端可存一份供回看（P2） |
| 作用范围 | 仅当前任务（v2.1 建议，待确认） | — |

**补偿双路径（2026-08-07 补充，与《三端双云说明书 §4.6》一致）**：

| 路径 | 补偿方 | 流程 | 标记 |
|------|--------|------|------|
| 路径一：本地设计→上位机加工 | **上位机（网页端）** | 网页下发探测 → 机器回传 `levelingResult` 网格 → 上位机重算补偿 G-code → 下发（机器按行执行，不再补偿） | `compensation: host` |
| 路径二：云端模型库→机器自主 | **固件** | 云端下发 G-code → 固件自主调平探测 + 实时网格补偿 + 换刀 | `compensation: firmware` |

**硬约束**：①**每次任务只有一个补偿方（二选一）**——`compensation` 是任务**属性声明**，让机器知道
"这段 G-code 是否已补偿过"（host=已补偿直接执行，firmware=固件实时补偿），防止**重复叠加（过补偿）**；
②两条路径**调平算法同一套**（D2），两端算出的补偿结果一致，标记只决定谁执行、不改变怎么算；
③协议新增：`levelingResult` 回传帧、任务补偿标记。

**补偿方式对比（建议选 B + 可视化）**：

| 方案 | 原理 | 优点 | 缺点 |
|------|------|------|------|
| A 上位机/云端重写 G-code | 双线性插值重写 Z 后推机器 | 不占 MCU 算力；G-code 即补偿版 | 需实现解析插值；G-code 体积变大；换参数要重新下发 |
| B 固件网格补偿（**推荐**） | 网格矩阵存 MCU，运动时实时 Z 补偿 | G-code 干净；与刀路解耦；grblHAL 有成熟 G29 实现 | 网格过密耗内存；需固件支持 |

> **决策（2026-08-06 内部评审 D2）**：**机器端固件与电脑端 ArtiMaker 的调平算法完全一致**
> （同一套算法/参数，双端各自实现），保证两端计算的网格与补偿结果一致；App 负责 UI 展示与参数下发。

### 2.3 断电续雕（保存状态 → 恢复）

| 项 | 归属 | 说明 |
|----|------|------|
| 保存状态快照 | **固件**（方案 B：写非易失存储） | v2.1 方案 A 上位机存临时文件——**淘汰**（上电后参考系易错乱） |
| 快照内容 | 固件 | 行号 / G54 偏移 / 刀具 / 主轴 / 进给 / 对刀结果 / 恢复点 |
| 恢复流程 | 固件主导 + 三端 UI 确认 | 上电 → 检测快照 → 提示用户 → 回零 → 恢复 G54 → 从断点继续 |
| 前提约束 | 用户 | 不得移动材料板与主轴；**ATC 任务不可断电续雕**（v2.1 约束） |

> 新协议帧草案：`{"cmd":"saveState"}` / `{"cmd":"restore","resume":true|false}`（见 §3）。

### 2.4 脱机雕刻（机器本地执行）

- v2.1：上位机传 G-code 到 TF 卡（HTTP multipart / YMODEM）→ 握手 `OLCRAFT` → `OLCRAFTSTART` 执行。
- **新框架天然取代**：G-code 由②/局域网服务**直推机器本地存储**，`startJob()` 即执行本地任务；
  断电脑/断 App 不影响加工。**不再需要单独的"脱机"概念**——机器本地执行成为默认形态。
- 遗留点：机器本地存储介质（Flash/TF）、任务队列管理（P2）。

### 2.5 延时摄影 / 短视频分享

| 项 | 归属 | 说明 |
|----|------|------|
| 触发 | App/电脑端（开始雕刻前勾选，时长 5/10/15s） | 已有 `aux timelapse` 开关（App 侧已具备） |
| 采集 | 摄像头（机器侧面固定头） | RTSP/RTMP 持续帧采集 |
| 合成/存储 | 云端 ①视频服务器 或 ②（P2） | 雕刻完成自动合成 15s 短视频 |
| 分享 | 三端 | 下载/分享链接（P2） |

### 2.6 视觉辅助定位（材料辅助定位）

| 项 | 归属 | 说明 |
|----|------|------|

## 3. 命令/接口映射（旧 `LY_` 帧 → 新 JSON 帧）

> 新协议规范见 `docs/PROTOCOL.md`（§2 命令表 / §2.3 状态广播）。下表把 v2.1 的 `LY_` 命令字
> 逐条映射到新 JSON；**标注【新增】的为需要补进 PROTOCOL.md 的扩展帧**（草案，待工程师确认）。

| 旧命令字 | 旧名称（v2.1） | 新 JSON 命令 | 状态 |
|----------|----------------|--------------|------|
| 0x0001 | DEVICE_HANDSHAKE（机型+协议版本） | TCP 连接建立即隐含；需要机型时 `{"cmd":"hello","model":"LY_3020_2.0","proto":1}` | 【新增】P2 |
| 0x0002 | DEVICE_STATUS | status 帧 `state`（idle/busy/alarm…） | ✅ 已有 |
| 0x0003/4 | FIRMWARE_VERSION(RESP) | `{"cmd":"firmwareVersion"}` | 【新增】P2（OTA 前用） |
| 0x1001/2 | ATC_OPEN / ATC_LOCK | `{"cmd":"atc","action":"open\|close"}`（半自动换刀用；自检流程内由固件自动执行） | 【新增】P1 |
| 0x2001/2 | PROBE_DOWN / PROBE_UP | `{"cmd":"probe","action":"down\|up"}` | 【新增】P1 |
| 0x3001 | OFFLINE_HANDSHAKE | 已被"G-code 直推机器本地执行"取代 | ❌ 退役 |
| 0x3002 | OFFLINE_UPLOAD | `{"cmd":"gcode","lines":[...]}`（局域网推送已有） | ✅ 已有 |
| 0x3003/4 | OFFLINE_START/STOP | `{"cmd":"job","action":"start\|stop"}` | ✅ 已有 |
| 0x4001 | ENGRAVE_PROGRESS | status 帧 `progress/eta` | ✅ 已有 |
| 0x5001–0x5006 | SAVE_REQUEST…DONE | `{"cmd":"saveState"}`（固件本地持久化） | 【新增】P1 |
| 0x5007–0x500A | RESTORE_QUERY…CANCEL | `{"cmd":"restore","resume":true\|false}`；上电后固件 status 带 `resumeAvailable:true` | 【新增】P1 |
| ACK(0x0000)/ERR(0x0001) | 超时重传/上报 | 新协议：命令帧建议带 `reqId`；固件回 `{"ack":reqId,"err":0}` 或 `{"ack":reqId,"err":码}`（TCP 下可用 status 帧携带） | 【新增】P1 待定 |

> **给嵌入式工程师**：旧 `LY_` 帧协议对新固件**不再适用**；新固件只实现 `PROTOCOL.md` §2 的
> JSON 命令/状态帧 + 上表【新增】扩展。电脑端新驱动也按同一 JSON 对接（一套协议三端复用）。

## 8. 开放决策点（需你 + 嵌入式/云端拍板）

1. **调平补偿方式**：选 B（固件网格补偿，推荐）还是 A（云端/上位机重写 G-code）？
2. **续雕快照**：固件本地持久化（方案 B，推荐）？是否同步云端备份一份？
3. **命令回执**：新 JSON 是否统一加 `reqId + ack/err`（建议加，三端与固件都好排查）？
4. **ATC 失败检测**：硬件能给到什么信号（传感器/电流/编码器）？没有则按"用户确认+急停兜底"。
5. **电脑端旧驱动**：v2.1 的 `LY_` 驱动是否正式退役，电脑端全面切新 JSON？（建议是）
