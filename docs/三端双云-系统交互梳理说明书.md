## 1. 系统概述

### 1.1 一句话

一台桌面 CNC 雕刻机（ESP32 控制 + 机身屏 + 摄像头），由 **手机 App / 电脑端 ArtiMaker / 机身屏**
三个终端共同操作；两台云端服务器（**视频推流** + **状态控制与模型库**）支撑远程访问与三端同步；
内网（局域网）与控制视频直连机器，外网经云端中转。

### 1.2 核心原则（所有实现必须遵守）

1. **ESP32 是唯一真值源（SSOT）**：坐标、刀仓、状态、自检/ATC/调平进度都由机器产生并广播，
   三端只渲染，不裁决、不代传。
2. **资产闭环（修正口径 2026-08-07，V2.4 细化）**：**App（消费端）永不持有真实 G-code**；
   **电脑端 ArtiMaker 与云端是 G-code 合法生产端**（可以生成/持有/切片），G-code 以**文件方式
   完整落地机器本地存储（SD/Flash）**后再执行；App 只取任务元数据 + 2D 预览矢量。
   > V2.4：**命令与文件分离**——MQTT/TCP 只传控制指令与**下载链接**；G-code 一律经
   > **HTTP 下载（预签名 URL）** 异步下载落盘，**不做流式/滴流传输**（详见 §4.6 D10）。
3. **高级功能归固件（默认）**：换刀/对刀/调平/断电续雕等涉及运动安全的序列由**固件拥有并执行**，
   各端只发高级意图（`atc start` / `leveling` / `saveState`）并监听广播。
   > 例外：**路径一（本地设计→上位机加工）**下，调平探测数据由机器回传、由**上位机（网页端）
   > 运算补偿后重写 G-code** 再下发——此时机器按"已补偿 G-code"执行；每次任务**只有一个补偿方
   > （compensation: host|firmware 二选一）**，见 §4.6。
4. **LAN/WAN 门禁**：内网直连 = 全功能（Jog/回零/开切）；外网 = **监视模式**（锁 Jog/开切，
   仅监控 + 暂停/停止）。
5. **三端不互传状态**：都订阅同一真值；App 与电脑端**不点对点直连**，统一经②同步。
6. **高风险动作须机旁物理确认（D9，2026-08-07）**：凡涉及**主轴起转**或**坐标大范围移动**的动作
   （含任务开始前的回零/移刀/起转），机器必须在**机身屏弹出高优先级「确认加工」界面**，强制用户
   在机器旁按**物理按钮**确认后才执行；未确认则保持待命。与 D3"远程功能参数无需屏上确认"**并存**
   ——D3 消除的是繁琐的屏上功能输入，D9 保留的是不可绕过的安全联锁。

## 2. 参与方与职责

### 2.1 三终端定位

| 端 | 角色 | 核心职责 | 真值源 |
|----|------|---------|--------|
| **机身屏**（机器终端） | **系统核心 / 机器侧 HMI** | 实时显示状态/坐标/进度/报警；**配网（AP + 机器唯一码）**；基础控制（暂停/急停/回零）；**高风险动作「确认加工」高优先级界面 + 物理按钮安全联锁**（D9）；断网兜底。远程任务/调平参数**功能上无需确认**（D3），但**动作上受物理按钮门禁** | ESP32（同机共享） |
| **手机 App**（alexcnc） | 移动控制/监控端 | 模型库→向导 6 步→控制；实时监控（状态+RTSP+2D 刀路）；远程监视；**按唯一码选择设备**（不做配网） | ESP32/②（本地只渲染） |
| **电脑端**（ArtiMaker） | 设计/切片工作站 + 控制端 | 🎨设计（资源库/AI/2D·2.5D）→ ⚙️生成（一键刀路/3D 预览/切片）→ 🔨制作（控制）；**调平算法与机器端完全一致**；不做配网 | 本地设计/切片；控制与状态来自机器 |

### 2.2 双云服务器职责

**① 视频推流服务器（媒体面）**

| 能力 | 说明 |
|------|------|
| 收流 | 机器把 RTSP 转推上来（RTMP/WebRTC/SRT） |
| 分发 | 外网三端经 HLS（低延迟档）/ WebRTC（实时档）观看；**内网直连 RTSP 不经它** |
| 地址注册 | 推流/播放地址上报②，由②分发给各端 |
| 录播（P2） | 延时摄影、加工回放 |

**② 状态控制 + 模型库服务器（业务面 · 三端同步中枢）**

| 域 | 能力 |
|----|------|
| 设备 | 注册/认证（**机器唯一码** + Token/证书）、在线状态、固件版本 |
| 状态 | 汇聚机器 statusStream 外网中转、报警推送 |
| 命令 | 外网控制转发（监视模式限权） |
| 模型库 | 灵感库、我的空间、历史记录 |
| 任务/G-code | 切片服务、TaskMetadata、**G-code 文件托管 + 预签名下载 URL 下发**（D10） |
| 材质 | 材质参数主表（三端共用 + 本地缓存） |
| 账户 | 登录/注册、**设备绑定（一账号多机，按唯一码）** |
| 诊断 | 日志上报、远程排障 |

### 2.3 已拍板决策（2026-08-06 内部评审）

| # | 决策 |
|---|------|
| D1 | 手机端/电脑端**不做配网**；配网（AP + 唯一码）归**机身屏** |
| D2 | **机器端与电脑端调平算法完全一致**（同一算法双端实现） |
| D3 | 机身屏**无确认类输入**：任务/调平参数下发即执行 |
| D4 | 内网同步按**方案 A（纯云端中枢）起步** |
| D5 | 鉴权按**机器唯一码**；外网 MQTT 加 Token/证书 |
| D6 | **一账号可挂多台机器**，按唯一码选择进入；**暂不支持同时连多台** |
| D7 | **联网与权限模型（2026-08-07 确认）**：所有终端常联网（路由器连外网），机器经机身屏配网后**始终在线**（②注册 + MQTT 长连接）；用户注册账号后输入/扫描唯一码绑定机器；**仅同一局域网可 Jog/开切**，外网只能监视 + 安全操作（暂停/停止/急停） |
| D8 | **双 G-code 生产路径 + 唯一补偿方（2026-08-07 确认）**：路径一（本地设计→上位机加工，上位机补偿 `host`）与路径二（云端模型库→机器自主，固件补偿 `firmware`）并存，场景决定；**每次任务只有一个补偿方**（`compensation` 为任务属性声明，防重复叠加）；两路径调平算法同一套（D2）；电脑端网页经**本地网关**（USB 串口优先 / WiFi TCP 备用）连机器 |
| D9 | **物理安全确认（2026-08-07 确认）**：任何端下发任务，凡涉及**主轴起转**或**坐标大范围移动**（含回零/移刀/起转），机器必须**机身屏弹出高优先级「确认加工」界面**，强制**机旁物理按钮**确认后才执行；未确认保持待命。是安全联锁，与 D3"远程功能参数无需屏上确认"并存 |
| D10 | **命令与文件分离 · G-code 落盘执行（2026-08-07 确认）**：MQTT/TCP 只传**控制指令与下载链接**；云端/网关下发 G-code 一律经 `job` 命令携带 **HTTP 预签名 URL**，ESP32 异步 **HTTP 下载到本地存储（SD/Flash）**后再执行；**不做流式/滴流传输**（网关同样整包传输落盘）。机器执行不依赖任何控制端在线，且与断电续雕快照持久化共用本地存储 |

## 4.5 联网与权限模型（2026-08-07 确认）

> 核心事实：**所有终端（机器/手机/电脑）都是联网的**，区别只在"是否在同一个路由器/网段下"；
> 且假定路由器都连外网（所有端理论上都能访问云端）。

- **机器始终在线**：机器经**机身屏配网**（屏幕搜索 WiFi → 输入密码）连上路由器后，向②注册
  （机器唯一码 + 在线状态），并保持 **MQTT 长连接** → 云端随时可见、可下发任务。
- **绑定流**：用户先在手机/电脑注册个人账户 → 通过**输入或扫描机器唯一码**把机器接入自己账号
  （一账号可挂多台，按唯一码选择进入）。
- **"内网"的真正含义 = 控制权差异**：
  - **同一局域网（同一路由器）**：App/电脑端直连机器（TCP:8899），**可以 Jog 点动 / 回零 / 开切**（实时控制）；
  - **4G/5G 或纯外网**：**不能实时控制（锁 Jog / 开切）**，仅**监视 + 安全操作**（暂停 / 停止 / 急停），经②中转。
- 判定方式：App/电脑端 mDNS 或同网段探测 → 同网段 = 全功能；否则走②监视模式。

> 补充两点：①外网仍保留**安全操作**（暂停/停止/急停），并非完全只读；②"扫描唯一码"为增强
> 交互（App 扫码，P2），先做输入唯一码。

## 4.6 G-code 生产路径与补偿归属（2026-08-07 补充）

> 背景：电脑端 ArtiMaker 是**网页版**，浏览器不能直接开 TCP/USB；且存在两条"把 G-code 送进机器"
> 的路径（本地设计 / 云端模型库），调平补偿归属不同。本节约定统一口径。

### 传输：网页端 → 本地网关 → 机器（D10：整包落盘，不做流式）

- **网页端不直连机器**：浏览器无法直接 TCP/USB。落地为 **ArtiMaker 网页 + 本地网关程序**：
  网页 ↔ 网关走 HTTP/WebSocket；网关 ↔ 机器走 **USB 串口（优先，网络不稳时更稳）或 WiFi TCP:8899（备用）**。
- **网关不做流式/滴流传输**：无论是 USB 还是 TCP，网关都把**完整 G-code 文件**传输并暂存到
  机器**本地存储（SD）**，全部到位后再发送启动指令（`startJob`）。理由：逐行滴流在数小时任务中
  一旦电脑休眠 / 浏览器标签冻结 / USB 松动即加工失败；**整包落盘后机器本地执行，不依赖任何
  控制端在线**，且与断电续雕快照持久化共用本地存储（D10）。
- 落地方式（二选一，**推荐 HTTP 下载**）：①局域网 server.py 提供 `GET /api/v1/gcode/{taskId}`
  下载端点，网关把 G-code 存到该服务后发 `job{gcodeUrl}`，机器 HTTP 下载——与云端路径完全同一套；
  ②小文件/调试场景保留 TCP `gcode` 帧（每行一帧）直传，正式流程以 ① 为准。
- 网关与机器之间命令帧格式**统一 JSON**（与 TCP:8899 完全一致，串口每行一帧）——固件只实现一套帧解析。
- ESP32 需提供一路 USB 串口（UART-USB 桥/原生 USB），作为稳定兜底通道。

### 两条路径（并存，场景决定）

| | 路径一：本地设计 → 上位机加工 | 路径二：云端模型库 → 机器自主 |
|--|------------------------------|------------------------------|
| G-code 来源 | 网页端（上位机）生成 | 云端②托管 |
| 调平归属 | **上位机**：下发探测 → 机器回传数据 → 上位机重算补偿 G-code → 下发 | **固件**：自主调平 + 换刀（方案 B）|
| 传输 | 网页→网关→**整包传输落机器 SD**（HTTP 下载优先 / TCP 帧兼容）→ `startJob` | ② MQTT 发 `job{gcodeUrl}` → 机器 **HTTP 下载落 SD** → 执行（App 只触发）|
| 补偿标记 | `compensation: host`（机器按行执行，不再补偿）| `compensation: firmware`（固件实时补偿）|
| 典型场景 | 专业设计、网络差、USB 直连 | 消费云模型、移动端触发 |
| 共同前提 | **D9 物理安全确认**：任务开始前（主轴起转/大范围移动）机身屏弹「确认加工」，机旁物理按钮确认后才执行 | 同左 |

### 三条硬约束

1. **每次任务只有一个补偿方（二选一）**：补偿要么由上位机（路径一）做、要么由固件（路径二）做，
   任务带 `compensation` **属性声明**——目的是让机器收到 G-code 时知道"这段刀路是否已补偿过"：
   已补偿（host）→ 直接执行不再叠加；未补偿（firmware）→ 固件做网格实时补偿。没有该标记机器
   无法判断，可能导致**重复叠加（过补偿）**。
2. **调平算法一致（D2）**：两条路径的调平算法**同一套**（上位机重算与固件网格计算相同算法/参数），
   两端算出的补偿结果一致；`compensation` 只决定"这次谁执行"，不改变"怎么算"。
3. **协议新增**：①调平探测结果**回传**帧（路径一）`{"cmd":"levelingResult","grid":[...]}`；
   ②任务补偿标记（startJob/gcode 帧带 `compensated`）；③USB 串口与 TCP 同帧（网关桥接）；
   ④D9：状态帧带 `awaitingConfirm`，新增 `confirm` 门禁（物理按钮按下由固件内部确认）；
   ⑤D10：`job` 命令带 `gcodeUrl`，机器 HTTP 下载落 SD 后 `startJob`。

## 5. 内网 / 外网 边界细则

| 维度 | 内网（同 Wi-Fi） | 外网（4G/异地） |
|------|----------------|----------------|
| 控制 | 直连 TCP:8899 全功能（Jog/回零/开切） | 经② MQTT，**监视模式**（锁 Jog/开切） |
| 状态 | 直连 5–10Hz | 经② 1–5Hz |
| 视频 | 直连 RTSP（200–500ms） | 经① WebRTC/HLS |
| 模型库/任务/材质/账号 | 经②（方案 A） | 经② |
| G-code | ②/局域网服务托管 → 机器 HTTP 下载落 SD（D10） | ② 托管 → MQTT 发 gcodeUrl → 机器 HTTP 下载落 SD |
| 断外网 | 控制+状态+RTSP 完整可用（模型库/任务同步受限） | 不可用（依赖云端） |
| 判定/鉴权 | 按**机器唯一码**匹配（mDNS/手动 IP 发现） | 唯一码 + Token/证书登录② |

## 8. 协议概览

- **传输**：局域网 **TCP:8899**（换行分隔 JSON 帧，双向）；网页端经**本地网关**桥接 **USB 串口**（优先）/ WiFi TCP:8899（备用），帧一致；外网 **MQTT**（`cnc/<deviceId>/cmd`、`cnc/<deviceId>/status`，帧格式一致）；REST 供云端接口。

- **D10 下载链路**：`job` 命令扩展 `gcodeUrl`（预签名 HTTP URL）→ 机器异步下载落 SD → 广播 `download` 进度 → 就绪后等 `startJob`；MQTT/TCP **不传文件本体**。
- **高级功能扩展帧（草案，待确认后并入 PROTOCOL.md）**：`atc(open|close)`、`probe(down|up)`、`saveState`、`restore(resume)`、`hello(model,serial,proto)`、`levelingResult(grid)`（路径一调平结果回传）、`confirm`（D9 物理按钮由固件内部触发，非网络命令）、任务补偿标记 `compensation: host|firmware`；建议统一 `reqId + ack/err` 回执。
- **云端 REST 扩展（已 mock）**：`POST /api/v1/tasks`（电脑端上传任务）、`GET /api/v1/library/mine|inspiration`；**新增 `GET /api/v1/gcode/{taskId}`（机器 HTTP 下载端点，D10）**。
- **旧协议退役**：v2.1 的 `LY_` 二进制帧协议（USB/WebSocket/串口）对新固件与电脑端新驱动**不再适用**，统一切 JSON。

## 12. 术语表

| 术语 | 含义 |
|------|------|
| SSOT | 唯一真值源：ESP32 广播的状态为唯一事实 |
| statusStream | 机器实时状态广播流（5–10Hz） |
| ATC | 自动换刀（含自动对刀联动） |
| TaskMetadata | 任务元数据（尺寸/材质/刀具/参数），非 G-code |
| 方案 A/B/C | 内网同步架构：纯云端中枢 / 局域网服务 / 混合 |
| 机器唯一码 | 出厂内置的设备唯一标识（绑定/鉴权/多机选择用） |
| 监视模式 | 外网只读模式：锁 Jog/开切，仅监控+暂停/停止 |
