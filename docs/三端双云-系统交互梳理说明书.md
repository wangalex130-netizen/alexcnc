## 1. 系统概述

### 1.1 一句话

一台桌面 CNC 雕刻机（ESP32 屏幕 + 主控 MCU + 独立摄像头板），由 **手机 App / 电脑端 ArtiMaker / 机身屏**
三个终端共同操作；**两台不同厂商的云**支撑远程访问与三端同步——**阿里云（业务面：账号/设备/任务/G-code/推送编排）** 与
**腾讯云（通信+媒体面：EMQX MQTT + 视频 relay）**；外加 **个推（GeTui）推送通道** 把机器事件直达 App。
内网（局域网）直连机器控制/视频，外网经云端中转，推送通知独立于控制链路常驻。

### 1.2 核心原则（所有实现必须遵守）

1. **ESP32 是唯一真值源（SSOT）**：坐标、刀仓、状态、自检/ATC/调平进度都由机器产生并广播，
   三端只渲染，不裁决、不代传。
2. **资产闭环（修正口径 2026-08-07，V2.4 细化）**：**App（消费端）永不持有真实 G-code**；
   **电脑端 ArtiMaker 与云端是 G-code 合法生产端**（可以生成/持有/切片），G-code 以**文件方式
   完整落地机器本地存储（SD/Flash）**后再执行；App 只取任务元数据 + 2D 预览矢量。
   > V2.4：**命令与文件分离**——MQTT/TCP 只传控制指令与**下载链接**；G-code 一律经
   > **HTTP 下载（阿里云预签名 URL）** 异步下载落盘，**不做流式/滴流传输**（详见 §4.6 D10）。
3. **高级功能归固件（默认）**：换刀/对刀/调平/断电续雕等涉及运动安全的序列由**固件拥有并执行**，
   各端只发高级意图（`atc start` / `leveling` / `saveState`）并监听广播。
4. **LAN/WAN 门禁**：内网直连 = 全功能（Jog/回零/开切）；外网 = **监视模式**（锁 Jog/开切，
   仅监控 + 暂停/停止/急停）。
5. **三端不互传状态**：都订阅同一真值；App 与电脑端**不点对点直连**，统一经云端同步。
6. **高风险动作须机旁物理确认（D9，2026-08-07）**：凡涉及**主轴起转**或**坐标大范围移动**的动作
   （含任务开始前的回零/移刀/起转），机器必须在**机身屏弹出高优先级「确认加工」界面**，强制用户
   在机器旁按**物理按钮**确认后才执行；未确认则保持待命。与 D3"远程功能参数无需屏上确认"**并存**。
7. **三层解耦（D11，2026-08-13）**：业务（阿里云 REST/DB）、通信（腾讯云 EMQX MQTT）、设备（固件）
   三者解耦；阿里云须作为 EMQX **常驻 bridge 客户端**，账号↔设备绑定与 ACL 由阿里云单一事实源维护并
   自动同步到 broker，**App/固件不直接写 ACL**（详见 §7 D12/D17）。
8. **推送通知是独立于控制链的第四通道（D13，2026-08-20）**：机器事件经 `notify` 帧→阿里云编排→
   个推→App，**不依赖 App 在线轮询或长连接**；即使 App 在后台/杀进程，关键事件（加工完成/报警/需机旁确认）
   仍能触达用户。个推 SDK 合规（隐私策略 + preInit）缺位会在严格 ROM 上**静默失败**（见 §4.7）。
9. **运动安全铁律（D14，2026-08-31）**：FeedHold/急停/限位/仓盖/防护门**全下位机本地闭环**；
   `state` 是 Jog **唯一闸门**，不得失真；断网发 `disconnected`，**绝不回落 idle**；雕刻中**禁 OTA/重启**；
   **禁"自动检测+自动补发"**。
10. **App 不远程启动雕刻（D15，2026-08-31）**：App 仅发 `startJob()` **触发**，真正的开切由机器
    `awaitingConfirm` 物理确认门禁放行；**App 永不远程自动开切**（防误操作）。
11. **多语言 / 灭乱码（D16，2026-09-05）**：设备/固件文本**只发代码或枚举**（state/alarm_code/
    material_code），App 端建「代码→多语言文案」映射；App UI 字符串抽 ARB（中/英），默认跟随系统语言。
    跨网络进来的中文一律 `utf8.decode`；UI 字体用系统字体（带完整中文回退），**禁用写死 `sans-serif`**（鸿蒙 resume 会丢字）。
12. **固件 OTA 为拉取式，非推送（D18，2026-09-08）**：服务器**不主动推送**“有新固件”；App 打开后**静默检查云端一次**（`checkCloudUpdate`），「我的」页「固件升级」入口显示绿色小点提示；用户点进固件升级页可手动升级机器/摄像头固件（进入页面亦自动核对云端）。**离线或打开 App 后无任何推送通知弹窗**。接口（`FIRMWARE_CHECK_URL`）未提供时安全不提示。详见 `docs/56` §3.8。

## 2. 参与方与职责

### 2.1 三终端定位

| 端 | 角色 | 核心职责 | 真值源 |
|----|------|---------|--------|
| **机身屏**（机器终端） | **系统核心 / 机器侧 HMI** | 实时显示状态/坐标/进度/报警；**配网（AP + 机器唯一码）**；基础控制（暂停/急停/回零）；**高风险动作「确认加工」高优先级界面 + 物理按钮安全联锁**（D9）；断网兜底。远程任务/调平参数**功能上无需确认**（D3），但**动作上受物理按钮门禁** | ESP32（同机共享） |
| **手机 App**（alexcnc） | 移动控制/监控/通知端 | 模型库→向导 6 步→控制；实时监控（状态+RTSP+2D 刀路）；远程监视；**个推推送接收**（加工完成/报警/需机旁确认）；**按唯一码选择设备**（不做配网） | ESP32/②（本地只渲染） |
| **电脑端**（ArtiMaker） | 设计/切片工作站 + 控制端 | 🎨设计（资源库/AI/2D·2.5D）→ ⚙️生成（一键刀路/3D 预览/切片）→ 🔨制作（控制）；**调平算法与机器端完全一致**；不做配网 | 本地设计/切片；控制与状态来自机器 |

### 2.2 云端（三层中的"云" = 两家独立云 + 推送通道）

> 2026-08-13 起，原②「状态控制+模型库服务器」**拆为阿里云（业务）与腾讯云（通信+媒体）两家独立云**；
> 推送单独走个推（③）。固件/设备为第三架构层（见 §1.3）。

**③ 阿里云（业务面 · 唯一业务事实源）**

| 域 | 能力 |
|----|------|
| 设备 | 注册/认证（**机器唯一码** + Token）；在线状态；固件版本 |
| 账号/绑定 | 登录/注册、**设备绑定（一账号多机，按唯一码）**；维护 `accountId ↔ deviceId` 映射（**五闸门模型**单次写入即全链路生效，见 D17） |
| 状态/命令 | 汇聚机器 statusStream 外网中转、报警推送编排 |
| 模型库 | 灵感库、我的空间、历史记录 |
| 任务/G-code | 切片服务、TaskMetadata、**G-code 文件托管 + 预签名下载 URL 下发**（D10，统一阿里云 HTTPS，broker 只传 URL） |
| 刀库 | **目录 catalog = 阿里云 DB 权威**（REST 持久化；变更经 EMQX retain 广播 `tool_catalog`，绝不推 `toolMap`）|
| 材质 | 材质参数主表（三端共用 + 本地缓存） |
| 推送编排 | 接收机器 `notify` 事件 → `resolve(deviceId→accountId)` → 调用个推下发到该用户 App |
| 跨云集成 | **bridge-aliyun**：EMQX 常驻持久客户端（admin/bridge 身份），绑定/解绑/刀库变更→ACL 与广播自动同步 |

**② 腾讯云（通信 + 媒体面）**

| 能力 | 说明 |
|------|------|
| MQTT Broker（EMQX） | 主题 `cnc/<deviceId>/cmd|status|notify|telemetry|log` + `cnc/broadcast/#` + `sys/#` + `tool_catalog(retain)` + `cnc/app/<accountId>/push`；**仅传控制指令/状态/下载链接，不传 G-code 文件本体**（D10）|

```
    → 用户点开始(App 仅发 startJob，D15) → 机器广播 awaitingConfirm
    → 机身屏弹「确认加工」高优先级界面 → 用户机旁按物理按钮
    → 固件自检(sc 0→5 广播) → 加工(progress/eta 广播) → 完成 → 阿里云编排个推 job_done → App 通知
```

**③ 外网远程监视**
```
App 4G → 登录② → 按唯一码选择机器 → ②汇聚状态(1-5Hz) + ①转发视频
    → 监视模式：可暂停/停止，Jog/开切锁定
```

**④ 断电续雕（高级功能）**
```
雕刻中 → 暂停 → 发 saveState → 固件持久化快照 → 断电
    → 上电 → status 带 resumeAvailable → 三端弹恢复入口 → 用户确认
    → 固件回零+恢复G54 → 从断点继续
```

### 4.5 联网与权限模型（2026-08-07 确认，V3.0 补充推送常驻）

> 核心事实：**所有终端（机器/手机/电脑）都是联网的**，区别只在"是否在同一个路由器/网段下"；
> 路由器连外网时三端都能访问云端。**推送通知独立于控制链路常驻**——即使 App 在后台/杀进程，
> 个推仍能触达（M13），不依赖 MQTT/REST 长连接。

- **机器始终在线**：机身屏配网连路由器后，向②（腾讯云 EMQX）注册（deviceId + 在线状态）并保持 **MQTT 长连接**；阿里云经 bridge 可见、可下发任务。
- **绑定流（五闸门）**：用户注册账号 → 输入/扫描机器唯一码 → 阿里云建立绑定并**自动同步 EMQX ACL**（D17）→ App 立即可用，零 broker 手动改动。
- **"内网"的真正含义 = 控制权差异**：
  - **同一局域网**：App/电脑端直连机器（TCP:8899），**可以 Jog/开切**（实时控制）；
  - **4G/5G 或纯外网**：**锁 Jog/开切**，仅**监视 + 安全操作**（暂停/停止/急停），经②中转。
- 判定：App/电脑端 mDNS 或同网段探测 → 同网段 = 全功能；否则走②监视模式。

### 4.6 G-code 生产路径与补偿归属（2026-08-07 补充，V3.0 注：统一阿里云托管）

> 背景：电脑端 ArtiMaker 是**网页版**，浏览器不能直接开 TCP/USB；存在两条"把 G-code 送进机器"的路径。
> **2026-08-14 拍板（D12③）：G-code 文件服务统一阿里云 HTTPS 托管**，broker 只传 URL，不传文件本体。

### 传输：网页端 → 本地网关 → 机器（D10：整包落盘，不做流式）

- 网页↔网关走 HTTP/WebSocket；网关↔机器走 **USB 串口（优先）或 WiFi TCP:8899（备用）**。
- 网关不做流式/滴流：完整 G-code 文件传机器**本地存储（SD）**后发 `startJob`。
- 落地方式（推荐 HTTP 下载）：局域网 server.py `GET /api/v1/gcode/{taskId}` 或**阿里云预签名 URL**，机器 HTTP 下载——两套同一执行引擎。
- 网关/机器间命令帧**统一 JSON**（与 TCP:8899 一致）；ESP32 提供 USB 串口兜底通道。

### 两条路径（并存，场景决定）

| | 路径一：本地设计 → 上位机加工 | 路径二：云端模型库 → 机器自主 |
|--|------------------------------|------------------------------|
| G-code 来源 | 网页端（上位机）生成 | 阿里云②托管（统一 HTTPS） |
| 调平归属 | **上位机**：下发探测 → 机器回传数据 → 上位机重算补偿 G-code → 下发 | **固件**：自主调平 + 换刀（方案 B）|
| 传输 | 网页→网关→**整包传输落机器 SD**（HTTP 下载优先 / TCP 帧兼容）→ `startJob` | ② MQTT 发 `job{gcodeUrl}` → 机器 **HTTP 下载落 SD** → 执行（App 只触发）|
| 补偿标记 | `compensation: host` | `compensation: firmware` |
| 典型场景 | 专业设计、网络差、USB 直连 | 消费云模型、移动端触发 |
| 共同前提 | **D9 物理安全确认** + **D15 App 不远程开切** | 同左 |

### 三条硬约束

1. **每次任务只有一个补偿方（二选一）**：`compensation` 任务属性声明，防重复叠加（过补偿）。
2. **调平算法一致（D2）**：两端同一套算法/参数。
3. **协议新增**：①调平探测结果回传 `levelingResult`；②任务补偿标记；③USB 串口与 TCP 同帧；④D9 `awaitingConfirm` + `confirm` 门禁；⑤D10 `job` 带 `gcodeUrl`（阿里云预签名），机器 HTTP 下载落 SD 后 `startJob`。

### 4.7 推送通知子系统（V3.0 新增 · 个推 GeTui 全链路）

> 背景：机器事件（加工完成/报警/需机旁确认）需**即时触达用户**，但 App 不能假设常驻前台。
> 故选**个推（第三方推送 SDK）**作为独立于 MQTT/REST 的第四通道（D13）。2026-08-27 创建独立应用
> `AlexCNC`（包名 `com.alexcnc.alexcnc`，AppID `2BrsBCR7hU9a1COnJw8P87`）；2026-09-06 接通主 App 点火线。

**角色与链路**
```
机器事件 → 固件 → ②(status/notify) → 阿里云推送编排(resolve deviceId→accountId)
        → 个推 API(CID/alias 定向) → App 端 onReceiveClientId/CID 就绪 → 本地通知+横幅
```
- **App 侧**：`getuiflut` 插件；`pushBootstrapProvider` 流程 `hydrate → initGetui(onCidReady 补报) → setUser(alias=userId) → bootstrap`。
- **绑定**：CID ↔ 用户 `alias`（=userId），按账号定向；登录态晚于启动时用 `authProvider.userId` 重绑，防漏绑。
- **典型通知（共 14 类，2026-09-08 起，`docs/56`）**：`job_done` / `alarm` / `confirm_required`（远程需机旁确认提示）/ `device online-offline` / `tool_changed` …（完整清单见 `docs/56`）。
- **固件 OTA 明确不走推送**：新固件到达**不**产生推送事件；升级提示为 App 内**拉取式绿点**（D18，§1.2 原则12 / §3.2）。

**合规红线（最易踩坑，2026-09-06 实测）**
1. **原生隐私合规两步必须在 `MainApplication.onCreate` 做**：`setPrivacyPolicyStrategy` + `preInit`；
   Flutter 插件**不会**做。缺了在**鸿蒙 AOSP / MIUI / HyperOS** 上**静默失败**——`init` 报 ok 但 CID 永远不来。
2. **gtsdk 运行时可见、编译期不可见**：任何原生集成（MainApplication/Activity）必须**反射**（`Class.forName`），
   禁止 `import com.igexin.sdk.*`（app 模块编译期 classpath 不含 gtsdk，会 `Unresolved reference`）。
3. **未同意隐私政策绝不初始化**：合规门控（SharedPreferences `push_privacy_accepted_v1`）拦截 `initGetui`。

**落地状态（2026-09-09）**
- `initGetui` + 隐私门控 + 调试页（`_PushDebugCard`：隐私状态/CID/诊断(init vs poll)/初始化按钮+30s 轮询）已落 main（`a826128d7f`）。

**通知权限（Android 13+，docs/53）**
- `POST_NOTIFICATIONS` 为运行时权限：首次进入需推送的场景（绑定成功/接收推送前）**主动请求**；用户拒绝后提供“去设置开启”兜底，且不阻断 App 其余功能。

## 7. 鉴权与多机管理

- **`deviceId` 是设备身份核心 = 屏幕 ESP32 MAC = 摄像头烧录 ID = 同一字符串**（量产烧录同一码，阿里云维护绑定）。
- **外网**：MQTT 连接用 Token/证书（clientId `screen-<deviceId>`）；REST 用账号会话。
- **内网**：TCP 连接按 `deviceId` 确认本机（防邻居误连）。
- **多机**：一账号挂多台 → App「我的 → 设备管理」按唯一码选择；当前**单机连接**（切换即断开上一台）。
- **阿里云 ↔ EMQX 集成（D11/D12/D17）**：阿里云以 `bridge-aliyun` 常驻客户端连 EMQX；账号↔设备绑定落库后，
  **自动下发 `cnc/sys/acl` 应用 ACL** + 广播 `tool_catalog`。App/固件**不直接写 ACL**。
- **五闸门模型（D17）**：阿里云控制台新增机器 → App 立即可用，**零 MQTT/broker 改动**（绑定/ACL 由阿里云 bridge 自动同步）。
- **EMQX 授权准则（D17）**：自动触发 = 无权限；人工触发 = 允许；`cnc-relay` 禁用；云网关允许但禁止自动重发。

## 8. 协议概览

- **传输**：局域网 **TCP:8899**（换行分隔 JSON 帧，双向）；网页端经**本地网关**桥接 **USB 串口**（优先）/ WiFi TCP:8899（备用），帧一致；外网 **MQTT（腾讯云 EMQX）** `cnc/<deviceId>/cmd`、`cnc/<deviceId>/status`、`cnc/<deviceId>/notify`、`cnc/<deviceId>/telemetry|log` + `cnc/broadcast/#` + `sys/#` + `tool_catalog`(retain) + `cnc/app/<accountId>/push`；REST 供云端接口。
- **`deviceId` 统一**：屏幕 ESP32 MAC = 摄像头烧录 ID = 同一 `<deviceId>`（量产烧录同一码）。
- **状态帧**：`state/pos/mpos/rpm/feed/progress/etaSec/scIndex/scTotal/aux/tools` + `download`（G-code 下载进度）+ `awaitingConfirm`（D9 等待机旁确认）（App 容错别名 mp/prog/eta）。
- **命令帧**：`jog/home/setWorkZero/spindle/aux/job(start|pause|resume|stop)/toolMap/leveling/gcode/confirm`。
- **D10 下载链路**：`job` 命令扩展 `gcodeUrl`（**阿里云预签名 HTTP URL**）→ 机器异步下载落 SD → 广播 `download` 进度 → 就绪后等 `startJob`；MQTT/TCP **不传文件本体**。
- **notify 帧（推送源，D13）**：`type ∈ {job_done, alarm, error, confirm_required, tool_changed, default}`，统一经个推推 App。
- **高级功能扩展帧**：`atc(open|close)`、`probe(down|up)`、`saveState`、`restore(resume)`、`hello(model,serial,proto)`、`levelingResult(grid)`、`confirm`（D9 物理按钮由固件内部触发）、任务补偿标记 `compensation: host|firmware`；建议统一 `reqId + ack/err` 回执。
- **云端 REST 扩展（已 mock）**：`POST /api/v1/tasks`、`GET /api/v1/library/mine|inspiration`、`GET /api/v1/gcode/{taskId}`（机器 HTTP 下载端点，D10）、`POST /api/v1/diagnostics`、设备绑定（阿里云）。
- **多语言（D16）**：设备/固件文本**只发代码/枚举**（state/alarm_code/material_code），App 建「代码→多语言文案」映射；不跨网络传中文文案。
- **旧协议退役**：v2.1 的 `LY_` 二进制帧协议对新固件与电脑端新驱动**不再适用**，统一切 JSON。

## 12. 术语表

| 术语 | 含义 |
|------|------|
| SSOT | 唯一真值源：ESP32 广播的状态为唯一事实 |
| statusStream | 机器实时状态广播流（5–10Hz） |
| ATC | 自动换刀（含自动对刀联动） |
| TaskMetadata | 任务元数据（尺寸/材质/刀具/参数），非 G-code |
| 方案 A/B/C | 内网同步架构：纯云端中枢 / 局域网服务 / 混合 |
| 机器唯一码 / deviceId | 出厂内置设备唯一标识 = 屏幕 ESP32 MAC = 摄像头烧录 ID（同一字符串）；绑定/鉴权/多机选择/ MQTT 主题均以其为准 |
| 监视模式 | 外网只读模式：锁 Jog/开切，仅监控+暂停/停止 |
| **三层架构** | 阿里云业务面（REST/DB/推送编排）+ 腾讯云通信+媒体面（EMQX MQTT + 视频 relay）+ 固件设备层 |
| **bridge-aliyun** | 阿里云作为 EMQX 常驻持久客户端（admin/bridge），绑定/解绑→ACL 与 `tool_catalog` 广播自动同步 |
| **ACL** | EMQX 访问控制列表；由阿里云 `cnc/sys/acl` 下发，App/固件不直接写 |
| **个推 / GeTui** | 第三方推送 SDK；独立于 MQTT/REST 的第四通道，把机器 notify 事件直达 App（D13） |
| **五闸门模型** | 阿里云控制台新增机器→App 立即可用，零 MQTT/broker 手动改动（D17） |
| **relay** | 视频中继（RTSP→HLS），中关村 39.106.144.53 / HK 43.154.192.242 |
| **olduva** | 产品品牌（2026-09-05 由 KARVA 更名） |
| **物料自动识别** | 立项：自动检测材料位置/形状/参数匹配无人化（复用俯视摄像头几何流水线 + 云端建模下发） |
| **断刀检测（方案 B）** | 立项：摄像头视觉 AI 火焰检测（YOLO-fire），倒逼带 NPU 硬件升级（RV1106/V851S/K230/ESP32-P4） |
| **多语言枚举** | 设备/固件文本只发代码/枚举（state/alarm_code/material_code），App 建「代码→多语言文案」映射（D16） |
| **拉取式固件升级（D18）** | 固件更新提示为 App 内拉取式：打开静默查云端一次 → 「我的」页绿点 → 点进手动升级；非推送、无弹窗（docs/56 §3.8） |
| **G-code 访问模型（D19）** | App 不本地生成 G-code，只云端下载；客户可下载本人刀路（数据主权），模型库源文件仅“发送机器”（docs/52） |
| **推送权限契约（D20）** | 个推只做通道，alias=userId 寻址（禁 CID 当业务标识）；Android 13+ 通知权限；控制类事件永不推送（docs/53） |
