## 二、关键事实修正（V2.4 与现状不符处）

| 主题 | V2.4 表述 | 现状（V3.0 修正） |
|------|----------|------------------|
| 云端构成 | ②「状态控制+模型库服务器」一台 | 阿里云（业务）+ 腾讯云（EMQX 通信 + relay 媒体）两家独立云 |
| 设备唯一码 | "机器唯一码"（泛指） | `deviceId` = 屏幕 ESP32 MAC = 摄像头烧录 ID（同一字符串，量产烧录） |
| G-code 托管 | ②/局域网 server.py | **统一阿里云 HTTPS 托管**，broker 只传 URL |
| 推送 | 完全未提及 | 个推 GeTui 第四通道，已接 App 主链路（cb039dc0），待真机验 CID |
| 刀库 | 目录/映射未区分 | catalog=阿里云 DB 权威（retain 广播），toolMap=固件运行时，绝不混写 |
| 运动安全 | D9 物理确认 | + D14 铁律（FeedHold/急停/限位/仓盖/防护门本地闭环；state 唯一闸门；断网 disconnected 不回落 idle）+ D15 App 不远程开切 |
| 品牌 | KARVA | **olduva**（2026-09-05 更名） |
| 多语言 | 未提及 | D16：设备文本只发枚举，App 建映射；UI 抽 ARB；灭乱码 |
| 构建/CI | c6348cb6；CI 把 ci-log.txt 推回 main | cb039dc0；CI 改用 artifact 不再污染 main；APK 自动下载到 apk/ |
| 授权模型 | "外网 MQTT 加 Token" | EMQX 授权准则：自动触发=无权限，人工触发=允许；cnc-relay 禁用；云网关禁自动重发；阿里云 bridge 自动写 ACL（五闸门） |

## 三、未决/待用户确认（文档已标注）

1. 个推 CID 真机验证（cb039dc0 APK 安装后 CID 是否真实到达）。
2. 机身屏物理按钮硬件形态（实体键 vs 触摸键）。3. 多语言 i18n 排期。
3. 物料自动识别 / 断刀检测立项与 NPU 硬件选型（RV1106/V851S/K230/ESP32-P4 待行业对比）。
4. 量产机器码烧录（等阿里云账户系统定稿）。
5. 五闸门模型落地字段与 EMQX ACL 边界案例复核。

## 四、推送建议

按"每次更新都推送到仓库"的既定约定，本说明书 V3.0 与差异清单建议随下次代码改动一起 push 到 main
（`docs/三端双云-系统交互梳理说明书.md` + `docs/三端双云-说明书更新差异清单-V2.4toV3.0.md`），供全团队阅读。
纯文档推送会触发 CI 构建（无害，但耗时），故本次若仅文档更新可单独 push 或并入下次代码提交。
