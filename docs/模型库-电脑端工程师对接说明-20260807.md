# 模型库 · 电脑端（ArtiMaker）对接说明

> 日期：2026-08-07 ｜ 对象：电脑端 ArtiMaker 工程师 ｜ 依据：`docs/模型库数据格式与接口定义.md`
> 目标：电脑端设计产出后，把模型/任务**按本格式上传到云端②**，App「图库 → 我的空间/灵感库」即可看到并可开切。
> 你的工作 = ①模型条目上传（§3/§4）②G-code 切片状态管理（§3 gcodeStatus）③加工任务触发（§4 jobs）。

---

## §1 你在整个链路中的角色

```
电脑端 ArtiMaker（设计/生成/制作） ──POST /api/v1/models──▶ ②云端 ──GET /api/v1/library──▶ App 图库
      │                                                                              │
      └──切片 G-code（gcodeStatus=sliced）──▶ ② 托管（D10：机器 HTTP 下载落盘后执行） ──▶ 机器
```

- 电脑端和云端是 **G-code 合法生产端**（可生成/持有/切片）；**App 永不持有 G-code**，只取元数据 + 2D 预览。
- 模型条目（本说明）是"菜谱"；点开始雕刻后由②实例化成加工任务（TaskMetadata）+ 直推 G-code。

---

## §2 你要做的三件事

| # | 事项 | 接口 | 说明 |
|---|------|------|------|
| 1 | **上传模型条目**（设计完成后） | `POST /api/v1/models` | 见 §4，字段见 §3 |
| 2 | **G-code 切片与状态** | 同上传接口（带 `gcodeStatus`） | 未切片 `unsliced` → 切片完成改 `sliced`（可开切） |
| 3 | **任务下发触发** | `POST /api/v1/devices/{id}/jobs` | App 点开始雕刻时②按任务 G-code 推机器（D10 下载链路） |

> 开发期：电脑端可先只做 1 和 2；3 已有现成 mock 可对接。

## §3 模型条目 JSON 格式（照着这个填）

```json
{
  "id": "mod-1001",
  "title": "复古木雕花纹板",
  "description": "适合新手的第一块浮雕",
  "author": "ArtiMaker",
  "category": "木雕",
  "tags": ["浮雕", "国风", "入门"],
  "difficulty": "入门",
  "coverUrl": "https://cdn.example.com/mod-1001/cover.jpg",
  "imageUrls": [
    "https://cdn.example.com/mod-1001/1.jpg",
    "https://cdn.example.com/mod-1001/2.jpg",
    "https://cdn.example.com/mod-1001/3.jpg"
  ],
  "widthMm": 145,
  "heightMm": 95,
  "depthMm": 3,
  "boardThicknessMm": 3,
  "duration": "38分钟",
  "durationSec": 2280,
  "materialKey": "pine",
  "materialPreset": "松木",
  "toolId": "t_flat_3175",
  "requiredTools": [
    { "toolId": "t_flat_3175", "role": "粗雕/轮廓" },
    { "toolId": "t_v60", "role": "精雕/刻线" }
  ],
  "recommendedSpindleRpm": 10000,
  "recommendedFeedRate": 1500,
  "previewUrl": "https://cdn.example.com/mod-1001/preview.json",
  "fileUrl": "https://cdn.example.com/mod-1001/model.svg",
  "gcodeStatus": "sliced",
  "isPublic": true
}
```

### 字段速查（必填 ★ / 建议 ◇）

| 字段 | 必填 | 说明 |
|------|:---:|------|
| `id` | ★ | 唯一标识（无则服务端自动生成） |
| `title` | ★ | 名称（列表主标题） |
| `category` / `tags` / `difficulty` | ★/◇/◇ | 分类（木雕/亚克力/金属/皮革/刻字）、风格标签、难度（入门/进阶/高手） |
| `coverUrl` / `imageUrls` | ★/◇ | 封面 + 多张实物图（URL 数组） |
| `widthMm` / `heightMm` / `depthMm` | ★ | 尺寸（mm）；**width/height 驱动 App 调平点数** |
| `boardThicknessMm` | ◇ | 推荐板材厚度 |
| `duration` / `durationSec` | ★/◇ | 雕刻时长：展示串 + 秒数（排序用） |
| `materialKey` | ★ | 默认材质 key（关联材质主表，**不写死显示名**） |
| `toolId` / `requiredTools` | ★/★ | 默认刀具 + **有序工序刀具**（粗雕→精雕；机器按工序自动换刀，与物理刀兜解耦） |
| `previewUrl` | ◇ | 2D 刀路预览矢量 JSON 地址（App 实时轨迹预览用，不给 G-code） |
| `gcodeStatus` | ◇ | `unsliced`（未切片）/ `sliced`（已切片，可开切） |
| `fileUrl` | ◇ | 模型源文件（.svg/.dxf/.stl，再设计/再切片用） |
| `isPublic` | ★ | true=灵感共享库 / false=我的空间 |

## §4 接口定义

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/v1/models` | **上传/更新模型条目**（body=§3 JSON；坏 JSON→400；返回 201 + id） |
| GET | `/api/v1/models/{id}` | 模型详情（全量） |
| GET | `/api/v1/library/inspiration?page=0&category=木雕` | 灵感库列表（精简字段，可分类过滤） |
| GET | `/api/v1/library/mine` | 我的空间列表（精简字段） |
| POST | `/api/v1/devices/{deviceId}/jobs` | 任务下发触发（②按任务 G-code 推机器，App 不持有） |

## §5 上传流程（电脑端实现参考）

```
① 设计完成 → 生成实物图/封面 → 上传图床/CDN → 拿 URL
② 切片 G-code → 生成 2D 预览 JSON（previewUrl）→ 取 materialKey/toolId/requiredTools
③ 组装 §3 JSON → POST /api/v1/models → 拿 201 + id
④ 校验：GET /api/v1/models/{id} 确认入库；gcodeStatus 从 unsliced → sliced
⑤ 更新（改参数/换图）→ 重复 POST 同 id 覆盖即可
```

---

## §6 关键约定（必须遵守）

1. **材质/刀具用 key/id 引用**（`materialKey="pine"`、`toolId="t_flat_3175"`），显示名由各端查主表渲染——不要自己塞"松木"这种名字当 key；
2. **图片只传 URL**：云端不存二进制；图床/CDN 方案待定（开发期可先用任意可达 URL）；
3. **时长双字段**：`duration`（"38分钟"）+ `durationSec`（2280），避免三端各自解析文本；
4. **列表接口返回精简字段、详情接口全量**——电脑端详情页拉 `GET /models/{id}` 即可；
5. **G-code 不进列表/不上传 JSON**：只填 `gcodeStatus` 状态位 + `previewUrl` 预览地址；实体 G-code 按 D10 走文件下载链路（机器 HTTP 拉取落 SD）。

## §7 与加工任务的关系（避免混淆）

| | 模型条目（你上传的） | 加工任务 TaskMetadata |
|---|---|---|
| 谁创建 | 电脑端设计产出 | ② 由模型实例化（用户选好材质/刀具后） |
| 内容 | 展示 + 默认参数 + 文件引用 | 实际参数 + 工序刀具 + G-code 状态 |
| App 用途 | 图库展示/筛选/向导预填 | 向导 6 步、调平点数、开切 |

> 你只需把模型条目传好；"点开始雕刻→②生成任务→推 G-code→机器执行"由 App/云端/机器完成。

## §8 待拍板（产品 + 电脑端一起）

1. **图片存储**：对象存储/CDN 方案（开发期先 URL）？
2. **分类体系**：固定枚举 vs 自由标签（建议枚举 + tags 自由）；
3. **难度档位**：入门/进阶/高手三档够吗？
4. **G-code 状态机**：是否加 `slicing`（切片中）中间态；
5. **requiredTools 工序刀具来源**：电脑端切片时自动生成，还是人工指定？（建议自动：按刀路类型）
