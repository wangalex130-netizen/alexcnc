# 模型库数据格式与接口定义（v1.0）

> 日期：2026-08-07 ｜ 用途：**电脑端 ArtiMaker ↔ 云端② ↔ App** 模型库对接的事实来源。
> 背景：软件工程师提出需梳理"服务器传哪些模型信息"（信息列表/实物图/雕刻时间/尺寸/默认材质/默认刀具）。
> 本文给出**完整字段格式 + 接口 + 与加工任务的关系**，供电脑端按此上传、App 按此渲染、云端按此存储。
> 相关：`docs/PROTOCOL.md` §3.1、`lib/models/library_item.dart`、`lib/models/task_metadata.dart`、`server/server.py`。

---

## 1. 核心概念：模型条目 ≠ 加工任务（先分清）

| | 模型条目（本文件） | 加工任务 TaskMetadata |
|---|---|---|
| 是什么 | 模型库里的"菜谱"——展示 + 默认参数 + 文件引用 | 用户点"开始雕刻"后实例化的"这顿饭" |
| 谁创建 | 电脑端/云端上传（设计产出） | ② 由模型生成（选好材质/刀具后） |
| App 拿它干嘛 | 图库展示、筛选、预览、向导预填 | 向导 6 步的加工参数、Step5 调平点数 |
| 包含 | 图/尺寸/时长/默认材质/默认刀具/源文件引用 | 实际参数 + requiredTools 工序 + G-code 状态 |

> 关系：`模型条目 → ② 生成 → 加工任务（+ 切片 G-code）`。App 只消费模型条目元数据 + 2D 预览，不持有 G-code。

## 3. 字段清单（分三层，优先级 P0 列表必填 / P1 详情与加工 / P2 运营与源文件）

### 3.1 P0 · 列表卡片（图库首页/灵感库网格展示，接口列表项只回这层）

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | string | 模型唯一标识 |
| `title` | string | 模型名称（列表主标题） |
| `coverUrl` | string? | **封面图**（列表缩略图；多图时取第一张） |
| `category` | string | 分类：木雕/亚克力/金属/皮革/刻字…（筛选 Tab） |
| `tags` | string[] | 风格标签：浮雕/国风/宠物/情侣…（搜索/推荐） |
| `difficulty` | string | 难度：入门/进阶/高手（新手筛选） |
| `duration` | string | 雕刻时长**展示串**："38分钟"（列表直接显示） |
| `materialPreset` | string | 默认材质**显示名**："松木"（列表角标） |
| `isPublic` | bool | true=灵感共享库 / false=我的云端空间 |
| `isHero` | bool | 焦点大图位 |
| `heroTag` | string? | 焦点角标："入门推荐""本周主推" |

### 3.2 P1 · 详情与加工参数（点开模型 → 详情页 + 向导预填）

| 字段 | 类型 | 说明 |
|------|------|------|
| `imageUrls` | string[] | **几张实物图**（详情轮播；与 coverUrl 第一张可重复） |
| `description` | string? | 模型简介 |
| `author` | string | 作者 |
| `widthMm` / `heightMm` / `depthMm` | number | **尺寸**（mm）；width/height 驱动 Step5 调平点数 |
| `boardThicknessMm` | number? | 推荐板材厚度（mm） |
| `durationSec` | number | 雕刻时长**秒数**（排序/统计用；与 duration 展示串并存） |
| `materialKey` | string | 默认材质 **key**（关联材质主表 → 转速/进给/下刀） |
| `toolId` | string | 默认刀具 id（关联刀具库） |
| `requiredTools` | [{toolId, role}] | **有序工序刀具**（粗雕→精雕；与物理刀兜 T1-T4 解耦，机器按工序自动换刀） |
| `recommendedSpindleRpm` | number? | 推荐转速（可选，通常由材质主表推） |
| `recommendedFeedRate` | number? | 推荐进给（可选） |
| `previewUrl` | string? | **2D 刀路预览矢量 JSON** 下载地址（App 只取渲染数据，不给 G-code） |
| `gcodeStatus` | string | `unsliced`（未切片）/ `sliced`（已切片，可开切） |
| `syncTime` | string? | 同步时间（我的空间显示） |
| `isHistory` | bool | 成功加工记录标记（历史复用） |

### 3.3 P2 · 源文件与运营（电脑端/云端生产端用，App 列表可不拉）

| 字段 | 类型 | 说明 |
|------|------|------|
| `fileUrl` | string? | 模型源文件下载（.svg/.dxf/.stl）——仅电脑端需要（重新设计/再切片） |
| `popularity` | number? | 热度（排序） |
| `rating` | number? | 评分 0-5 |
| `createdAt` / `updatedAt` | string? | 上架/更新时间（ISO 8601） |

## 4. 关键设计约定（对接双方必须遵守）

1. **材质/刀具用 key/id 引用，不用硬编码名**：`materialKey`/`toolId` 关联云端主表（材质表、刀具编号表），
   **显示名由各端查主表渲染**；`materialPreset` 只是列表上的便捷显示名，可省略（App 查主表兜底）。
2. **图片统一用 URL 数组**：`imageUrls` 多图 + `coverUrl` 封面（= 第一张）。上传时电脑端先传图到
   图床/CDN，拿 URL 再填；云端只存 URL 不存二进制。
3. **时长双字段**：`duration`（展示串）+ `durationSec`（秒数），避免三端各自解析"38分钟"。
4. **列表接口精简、详情接口全量**：`GET /library/*` 只回 P0（省流量），`GET /models/{id}` 回 P0+P1+P2。
5. **G-code 不进列表**：模型条目只有 `gcodeStatus` 状态位 + `previewUrl` 预览；实体 G-code 由电脑端/云端
   上传后直推机器（D10 模型），App 永不持有。

## 5. 接口定义

| 方法 | 路径 | 返回 | 用途 |
|------|------|------|------|
| GET | `/api/v1/library/inspiration?page=0&category=木雕` | `[LibraryItem 精简]` | 灵感库列表（可分类过滤） |
| GET | `/api/v1/library/mine` | `[LibraryItem 精简]` | 我的空间（含电脑端上传的模型） |
| GET | `/api/v1/models/{id}` | 模型全量 | 详情页 / 向导预填 |
| GET | `/api/v1/models/{id}/preview` | 2D 矢量 JSON | 刀路预览渲染 |
| POST | `/api/v1/models` | `201 {"ok":true,"id":...}` | **电脑端上传模型**（body=本文件 §2 JSON，含多图 URL；坏 JSON → 400） |
| PATCH | `/api/v1/models/{id}` | `200` | 更新模型（电脑端改参数/换图） |
| DELETE | `/api/v1/models/{id}` | `200` | 下架/删除（我的空间） |

## 7. 待确认（软件工程师 + 电脑端同事）

1. **图片存储**：云端图床/CDN 方案？还是先直接存 URL（开发期）？（建议：先 URL，量产后接对象存储）
2. **分类体系**：`category` 用固定枚举（木雕/亚克力/金属/皮革/刻字/其他）还是自由标签？（建议：枚举 + tags 自由）
3. **难度等级**：三档（入门/进阶/高手）够用吗？
4. **G-code 状态机**：`unsliced → slicing → sliced → 加工中 → 完成` 是否需要"切片中"中间态？（建议要）
5. **电脑端上传是否走同一 `POST /api/v1/models`**（建议是，App 与电脑端共用一套模型库接口）？
