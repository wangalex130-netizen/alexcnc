### 断点根因（三条，全部有据）

**① `homed` 死锁 —— 本次联调最大的拦路虎**

- 固件状态帧全字段（`pingMu-3020/main/cnc_net.c` → `build_status_json`）：
  `state / pos / mpos / rpm / feed / progress / etaSec / jobState / jobId /
  jobMessage / scIndex / scTotal / download / awaitingConfirm / msg /
  alarm_code / door / spindle / grbl_online / log* / ts / aux / tools`
  —— **没有 `homed`**。
- App 侧 `MachineStatus.homed` 于是恒为 `null`；而定原点页三处把它当硬门禁
  （`st.homed != true` 即拒）⇒ 状态灯永远「检查机器」、【移动到此】永远灰。
- 讽刺的是：`machine_status.dart` 的字段注释早就写明
  「**帧里没有该字段时为 null（未上报）**……未上报时 UI 只黄字提醒，**不硬拦**（老固件兼容）」
  —— 是页面实现漂移成了硬拦。
- **修法**：只认「**明确 false**（确实未回零）」才锁。
  放行的依据不是放宽标准，而是另一道闸门已经存在：
  **未回零且开启限位（`$22=1`）时 GRBL 处于 Alarm，`state` 不会是 `idle`，
  上一句 `canControl` 已经拦住**；能走到移动那一步，说明机器本身可运动、`mpos` 自洽。

**② `setWcsOffset` 固件没有 → 假阳性「已写入」**

- 固件命令表里与零点相关的只有 `set_work_zero`，它内部发的是 **`G92 X0 Y0`**
  = 把**当前位置**设为工件零点，**没有「写入任意偏置值」的能力**。
- 所以 App 原样发 `{"cmd":"setWcsOffset"}` 会落进 `unknown cmd` 分支回 `E400`，
  而 App 端 `_dispatch` 只确认「发出去了」⇒ 界面报「已写入」，机器毫无反应。
- **修法**：走 `manual_gcode` 发 GRBL 原生 **`G10 L2 Pn X.. Y..`**
  （P1=G54 … P6=G59），它本身就是「写工件坐标系偏置」，与 App 的
  `payload.g54For()` 给出的偏置值（`DesignPos − camOriginOffset`）**语义逐字对应**。
  **不带 Z**（App 拿不到 Z 行程/零点数据 ⇒ 不介入 Z，延续既有 Z 铁律）。

**③ `framing` 固件没有 → 假成功「已巡边一圈」**

- 固件未实现 `framing`（→ `E400`），但 App 的文案却宣称
  「机器抬 Z 至最高安全位后激光巡边一圈」——**两个都未经核实**：
  既没有 `framing`，也没有「抬 Z」。
- 联调时最怕这种：**把「固件没做」误判成「App 做完了」**。
- **修法**：改为如实文案——只说「指令已发出」，并提示
  「若机器没有动作，说明当前小屏固件版本还不支持巡边」。

## 2. 云端还没有轻量 JSON 怎么办？—— 有现成通道，不用等后端

**路径**：`我的 → 本地文件解析（调试）`

那里有两个开关/按钮，正是为当前状态做的：

| 设施 | 作用 |
|---|---|
| **「载入内置 Full 级样例」** | 一键载入**内置**的 Full 级载荷（含 16 位高程网格 128×80）⇒ 3D 预览立刻有真数据。内置的理由是「把文件拷进手机 / 在鸿蒙上选对文件这两步最容易出错」 |
| **「模拟机器位」** | 打开后取点/Jog 改用虚拟位，**在没有机器的情况下把定原点整页跑通**（只动虚拟位、不发任何指令） |

**设计边界（都已在代码里保证）**：

- **云端 `payloadUrl` 永远优先**；本地载荷只在云端缺失/失败时接管
  ⇒ 后端将来注入 `payloadUrl` 后**不需要改 App、也不会冲突**；
- 仅**本次进程**有效，不落盘，App 重启即清；
- 存的仍是**轻量 JSON**，App 依旧**不解析 G-code**（架构铁律未破）。

> ⚠️ 所以联调时**不要**因为看到 3D 是占位就以为「3D 功能没做出来」——
> 那是云端还没给数据。先载入内置样例。

## 3. 联调回归清单（按依赖顺序，逐阶段验收）

### 阶段 0 · 装包
- [ ] 装**联调包**（`-联调包-可连MQTT.apk`），不是正式包。正式包无凭据、证书强校验，连不上是**预期**。
- [ ] 确认手机与机器在**同一 Wi-Fi**。

**判据**：App 内机器列表能看到在线设备。

### 阶段 1 · 连接与状态帧（最基础，先过这关）
- [ ] 打开机器，App 进入控制台/工作台。
- [ ] 看**状态卡**：`state` 是否随机器动作变化（idle ↔ busy）。

**判据**：能读到 `state` + `mpos` + `pos`。
**注意**：`state` 是**唯一权威**（未知值一律按「未知」处理，绝不回落 idle —— 这是防撞刀的安全设计）。

### 阶段 2 · 点动（回归验证「以前 OK 的」）
- [ ] 单步点动 X / Y，每档距离都试一遍。
- [ ] 确认**松手即停**、机器实际走了对应距离。

**判据**：机器按 `$J=G91` 相对移动，UI 有位移。
**若不动**：看 `cnc/<id>/notify` 的 `cmd_ack`（见 §5 排障口诀）。

### 阶段 3 · 云端雕刻（回归验证「以前 OK 的」）
- [ ] 模型库选一个模型 → 走向导 → 触发雕刻。
- [ ] 观察 `prepare_job`（下载+校验）→ `confirm`（确认）→ 进度。

**判据**：屏幕端能收到并开始走 G-code；App 显示进度。
**这条链路不依赖轻量 JSON**（只传 G-code 的 URL + 元数据），云端没 JSON 也能测。

### 阶段 4 · 定原点页（本轮修复的重点）
前置：先在 `我的 → 本地文件解析（调试）` 载入内置样例。
- [ ] **取点**：状态卡显示 `mpos` 数字 → 取 2 点（矩形对角 / 圆对面）。
- [ ] **拖动走位**：画布空白处拖出琥珀十字 → 点【移动到此】→ **本轮修好后应能真的走**。
- [ ] **写入 G54**：本轮改为发 `G10 L2 P1 X.. Y..`。
- [ ] 走边框：**预期仍不通**（工单 F2），文案会如实说明。

**判据**：`mpos` 在动、G54 生效（可用点动验证工作坐标归零）。
**真机自查**：若【移动到此】仍灰，先看手柄条状态文字：
`就绪·回零未上报` = 正常（固件不上报 homed，已放行）；
`检查机器` = `state` 不是 idle；`未连接` = MQTT 断了。

## 5. 联调排障口诀（命令到底成没成）

**所有命令都带 `reqId`**（App 侧 `_publish` 自动注入，无需手工加），
固件把结果回执发到 **`cnc/<deviceId>/notify`**，格式：

```json
{"type":"cmd_ack","reqId":"...","ok":true,"code":"OK","data":{"cmd":"jog"}}
```

App 已做两件事：**① 按 `reqId` 关联**；**② 把错误码翻成中文**
（避免把 `GRBL reply timeout` 这种原文直接甩给客户）。

| 回执 code | 真实含义 | 谁的问题 |
|---|---|---|
| `OK` | 成功 / 已被接受 | — |
| **`E400` + `unknown cmd`** | **固件版本不认识这条命令** | 固件（或 App 发了未实现指令） |
| `E409` | 机器忙 / 作业状态不允许 | 正常保护 |
| `E501` | 功能明确标注「未实现」（如 `ota`） | 固件 |
| `ENETDOWN` | 小屏 Wi-Fi 离线 | 网络 |
| `EVERIFY` | G-code 下载/校验失败 | 云端文件 |

**排查顺序**：① 命令发出去了吗（MQTT 连没连）→ ② 收到 `cmd_ack` 了吗
→ ③ `ok` 真假 + `code` 是什么 → ④ 固件是否认识这条命令（查 §1 表）。
**不要跳过 ①②③ 直接猜代码。**

## 6. ⚠️ 一个不要打开的开关

`--dart-define=JOG_CONTINUOUS=true`（连续点动）**目前不要启用**：

- 它的松手取消走 `jog_cancel`，保活走 `jog_keepalive`，**这两条固件都不认**（→ `E400`）；
- 后果：**松手后机器仍会走完 `$J` 的目标距离**，不是「松手即停」；
- 该开关默认关闭，本次不启用 ⇒ **不影响当前联调**。
- 若将来要用连续点动，须先让固件实现 `jog_cancel`（或改用 GRBL 实时字符 `0x85` 的通道）。
