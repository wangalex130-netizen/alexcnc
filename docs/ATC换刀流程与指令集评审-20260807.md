## 1. 流程图重构（从 .pos 还原）

### 1.1 上位机 · 设置刀仓（x≈1300–1700 区）

```
设备上电 → 上位机连接 → 读取刀仓信息($KNIFE_INFO) → 显示刀仓信息
    → 设置刀仓
    → 设置 4 个刀仓分别存放什么刀($KNIFE_SET)
        → [刀具重叠?] ── 重叠 → 是否覆盖刀仓刀具($KNIFE_COVER)
        │                     ├─ 覆盖 → 更新刀仓信息 → 回主界面
        │                     └─ 不覆盖 → 更换其他刀仓 → 回主界面
        └─ 不重叠 → 更新刀仓信息 → 回主界面
```

### 1.2 执行换刀（雕刻时，x≈2000–2240 区）

```
执行换刀($KNIFE_REPL)
    ├─ 当前有刀 且非目标刀 → 读取当前刀具刀仓坐标($KNIFE_GET)
    │      → 执行放刀动作($KNIFE_RELEASE 或 REPL 内置放刀)
    │      → 放刀完成 → 读取目标刀具刀仓坐标 → 执行取刀动作 → 取刀完成
    ├─ 当前无刀 → 读取目标刀具刀仓坐标 → 执行取刀动作 → 取刀完成
    └─ 当前刀具 == 目标刀 → 不做动作
    → 更新刀具信息到存储($KNIFE_INFO 可查 CURRENT/SLOT)
```

### 1.3 雕刻前（x≈1595 区）

```
选择雕刻文件 → 设置雕刻刀具 → 检查放刀仓位限位触发情况(防放刀位有刀)
    → 执行雕刻 → 正常雕刻
```

## 2. 指令集清单（换刀指令集.xlsx，11 条）

| 指令 | 功能 | 回复 | 阶段 |
|------|------|------|------|
| `$KNIFE_SAVE_XY=T1:X800Y500` | 保存/更新 1 号刀仓坐标（mm，可存 4 个） | `[KNIFE:OK]` / `[ERROR:XY,EXC]` | 设置刀仓 |
| `$KNIFE_SET=T1:#5` | 设置 1 号刀仓存放 5 号刀 | `[KNIFE:SET=T1:#5]` / `[ERROR,SET=T1:#6]` | 设置刀仓 |
| `$KNIFE_NEW=#6` | 登记当前主轴刀具为 6 号（换刀前发给上位机提醒确认） | `[KNIFE:NEW=#6]` | 设置刀仓/手动装刀 |
| `$KNIFE_INFO` | 查询刀库全部信息 | `[KNIFE:CURRENT=6][KNIFE:SLOT1=#5,X=800,Y=500]...` | 查询 |
| `$KNIFE_GET=T1` | 查询单个刀仓（含 LIMIT 限位） | `[KNIFE:SLOT1=#5,X=800,Y=500,LIMIT=0]` | 查询 |
| `$KNIFE_STATUS` | 查询换刀状态 | `[KNIFE:IDLE,CURRENT=#6]` / `[KNIFE:RUNNING,TARGET=#2]` / `[ERROR:STATUS]` | 换刀 |
| `$KNIFE_ABORT` | 中止换刀 | `[KNIFE:OK]` | 换刀 |
| `$KNIFE_COVER=T1:#5` | 强制覆盖仓位刀具信息（仓位显示有刀时） | `[KNIFE:COVER=T1:#5]` | 设置刀仓 |
| `$KNIFE_RELEASE` | 放刀：当前主轴刀具放回相应刀仓 | `[KNIFE:OK]` / `[ERROR:RELEASE]`（无存放位置） | 换刀 |
| `$KNIFE_REPL=#2` | 换刀：主轴换 2 号仓刀具（有刀先放、无刀直接取） | `[KNIFE:REPL=T2:#5]` / `[ERROR:REPL=T2:#0]`（2 号仓无刀） | 换刀 |

> 备注：T=刀仓编号 1~4；#=刀具编号（全局统一，如 1/8V 刀=#1、1/16 铣刀=#2；**#0 表示空位/无刀**）。

## 3. 总体评价

**流程与分工方向完全成立**，和我们在《开发总纲》里"ATC 序列归固件、上位机只发意图"的决策一致：
- ✅ **检测前置**（设置刀仓阶段完成"仓位有刀/是哪把刀"的登记）→ 雕刻时换刀只按登记执行，逻辑闭环；
- ✅ **雕刻前限位检查**（放刀位限位）保留为安全动作，说明"仓位有无刀"的硬检测并没有被完全去掉；
- ✅ 指令覆盖了：登记（SET/NEW）、坐标（SAVE_XY）、查询（INFO/GET/STATUS）、强制覆盖（COVER）、
  放刀（RELEASE）、换刀（REPL）、中止（ABORT）。

**但有一个关键概念需要先统一（也是评审的核心结论）：**

> **"刀具识别检测"（软件判定仓位里是哪把刀）与"仓位安全限位"（传感器判定有刀/无刀）是两回事。**
> 前置到设置刀仓阶段的应只是"刀具识别登记"；**"仓位限位校验"必须保留在每次放刀/取刀动作内**（固件内置，
> 不可被"执行换刀不检测"的设计去掉）。你们流程里"检查放刀仓位限位触发情况"节点已经体现了这个思想，
> 但它的位置建议从"上位机雕刻流程步骤"改为"固件换刀动作前置步骤"（见 §4-1）。

## 4. 问题清单（按严重度排序）

### 4.1 【安全·必须改】限位检查归属：应内置固件换刀动作，而非上位机步骤

流程中"检查放刀仓位限位触发情况"画在"设置雕刻刀具 → 执行雕刻"之间，由上位机流程触发。
**风险**：若上位机/连接异常（断网、App 被杀），该检查可能不执行 → 放刀位有刀时放刀即撞刀。
**建议**：放刀/取刀动作的**限位自检由固件内部强制**（每次 REPL/RELEASE 前：校验放刀位无刀、
取刀位有刀），上位机只做展示；这符合"运动安全必须下位机闭环"的铁律（PROTOCOL.md 决策②）。

### 4.2 【安全·建议】$KNIFE_REPL 执行时的最低限度校验（与"不检测"不冲突）

"执行换刀不再做刀具检测"应限定为**不再做刀具编号识别**；但 REPL 前固件仍应校验：
- 目标仓位限位状态（取刀位应有刀、放刀位应无刀）——这是动作安全，不是刀具识别；
- 当前主轴刀具是否登记过存放位置（无登记 → 提示用户先手动放回/确认，避免 $KNIFE_RELEASE 的 ERROR:RELEASE 场景在换刀中途出现）。
**理由**：刀仓登记是"人写的记录"，限位是"传感器的实时事实"；换刀动作必须相信传感器，不能只信记录。

### 4.3 【逻辑·建议】"设置雕刻刀具 → 检查限位 → 执行雕刻"的时序位置

现在"检查放刀仓位限位"在"设置雕刻刀具"之后，但换刀动作（REPL）其实发生在"设置雕刻刀具"这个环节。
建议流程表述改为：`设置雕刻刀具 → 执行换刀(REPL，固件内置限位自检) → 换刀完成确认(读 KNIFE_INFO)
→ 执行雕刻`。把"限位检查"并进换刀动作，流程更顺、也更安全（避免"检查了限位但没换刀/换了刀但没检查"的错位）。

### 4.4 【健壮性·建议】换刀失败后的状态恢复未定义

$KNIFE_STATUS 有 `[ERROR:STATUS]`、$KNIFE_ABORT 可中止，但**失败/中止后机器停在什么状态、
如何恢复、刀是否在中间位置**没有定义。建议明确：
- REPL 失败 → 固件进入 `alarm` + 广播失败原因（哪一步：放刀/取刀/限位）→ 三端弹窗；
- 恢复路径：手动干预（用户按流程人工放回/取出）+ 重新登记（$KNIFE_NEW/$KNIFE_SET）→ 再试或放弃本次任务。

### 4.5 【细节·建议】#0 空仓语义显式化

$KNIFE_INFO 里 SLOT3=#0 表示空位，但指令表没写明"用 $KNIFE_SET=T1:#0 清空仓位"。
建议显式声明：**#0=空仓，$KNIFE_SET=T1:#0 可清空仓位**（这是上位机"更换其他刀仓/清空仓位"的基础指令）。

### 4.6 【协议·必须补】全局刀具编号表缺失

备注说"#为刀具编号(后续统一规定,不做更改)"——但**编号↔刀具型号的对照表**（#1=1/8V 刀、#2=1/16 铣刀…）
目前只存在于口头/备注。这台机器将来三端（机身屏/App/电脑端）+ 云端都要显示刀具名，**编号表必须落成
正式协议文档**（PROTOCOL.md 附录），否则上位机显示的刀名和 App 显示的对不上。
建议字段：`#编号 / 中文名 / 直径 / 类型(平底/球头/V刀/尖刀) / 常用参数`，与现有 `Tool` 模型对齐。

### 4.7 【体验·建议】设置刀仓阶段的"检测→登记"交互在流程图上不完整

用户意图是"所有刀具检测放在设置刀仓流程中"，但流程图"设置 4 个刀仓分别存放什么刀"只有一步。
建议展开为（这也正是上位机侧重该阶段的原因）：
```
装刀入仓 → 读取仓位限位($KNIFE_GET 查 LIMIT，确认有刀)
    → 上位机显示"1号仓有刀" → 用户选择该刀编号 → $KNIFE_SET=T1:#n
    → 示教/录入刀仓坐标 → $KNIFE_SAVE_XY=T1:X..Y..
    → 冲突检测(编号重复/坐标越界) → 更新刀库($KNIFE_INFO 复核)
```

## 5. 指令完备性结论（上位机·设置刀仓阶段）

**基本够用**。已有 6 条覆盖设置刀仓核心操作（INFO/SET/SAVE_XY/GET/COVER/NEW）。需补充/明确的：

| # | 缺口 | 建议 |
|---|------|------|
| 1 | **清空仓位指令** | 显式声明 `$KNIFE_SET=T1:#0` = 清空（或将 #0 语义写入指令表） |
| 2 | **全局刀具编号表** | PROTOCOL.md 附录新增"刀具编号字典"（#n ↔ 型号/直径/类型），三端+云端共用 |
| 3 | **LIMIT 字段语义** | $KNIFE_GET 的 LIMIT 需明确：0=无刀/1=有刀（限位触发），供上位机"检测有刀"使用 |
| 4 | **$KNIFE_NEW 双向确认** | 建议回复带"当前刀号 + 来源"（手动登记 vs 自动换刀结果），避免歧义 |
| 5 | **换刀失败/中止状态机** | 定义 ERROR 后机器状态与恢复流程（§4.4） |
| 6 | **坐标示教方式** | $KNIFE_SAVE_XY 是上位机填坐标；建议补充"手动对刀仓示教"（Jog 到位置 → 记录当前坐标）指令或复用现有 jog+setWorkZero 流程 |
