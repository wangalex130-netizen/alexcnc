## 1. 流程图重构（从 .pos 还原，与 V1 相同）

### 1.1 上位机 · 设置刀仓
```
设备上电 → 上位机连接 → 读取刀仓信息($KNIFE_INFO) → 显示刀仓信息
    → 设置刀仓 → 设置 4 个刀仓分别存放什么刀($KNIFE_SET)
        → [刀具重叠?] ── 重叠 → 是否覆盖($KNIFE_COVER) → 覆盖→更新 / 不覆盖→更换其他刀仓 → 回主界面
        └─ 不重叠 → 更新刀仓信息 → 回主界面
```

### 1.2 执行换刀（雕刻时）
```
执行换刀($KNIFE_REPL)
    ├─ 当前有刀 且非目标 → 读取当前刀具刀仓坐标 → 放刀 → 放刀完成 → 读取目标刀具刀仓坐标 → 取刀 → 取刀完成
    ├─ 当前无刀 → 读取目标刀具刀仓坐标 → 取刀 → 取刀完成
    └─ 当前刀具 == 目标 → 不动作
    → 自动对刀(Z-Probe) → 更新刀具信息到存储
```

### 1.3 雕刻前
```
选择雕刻文件 → 设置雕刻刀具 → 检查放刀仓位限位触发情况 → 执行雕刻 → 正常雕刻
```

## 2. 指令集清单（V2 建议版：原 11 条 + 修正 2 条 + 新增 2 条）

| 指令 | 功能 | 回复 | 阶段 | 变更 |
|------|------|------|------|------|
| `$KNIFE_INFO` | 查询刀库全部（CURRENT/SLOT 刀号+坐标+LIMIT） | `[KNIFE:CURRENT=6][KNIFE:SLOT1=#5,X=800,Y=500,LIMIT=1]...` | 查询 | 原样 |
| `$KNIFE_GET=T1` | 查询单个刀仓（**含 LIMIT 物理限位**） | `[KNIFE:SLOT1=#5,X=800,Y=500,LIMIT=0]` | 查询/校验 | 原样（LIMIT 语义需明确：0=无刀/1=有刀） |
| `$KNIFE_SET=T1:#5` | 登记仓位刀具编号（**#0 = 清空仓位**） | `[KNIFE:SET=T1:#5]` / `[ERROR,SET=T1:#6]` | 设置刀仓 | #0 语义显式化 |
| `$KNIFE_COVER=T1:#5` | 强制覆盖仓位登记（仓位显示有刀时） | `[KNIFE:COVER=T1:#5]` | 设置刀仓 | 原样 |
| `$KNIFE_SAVE_POS=T1:X800Y500Z-15` | 保存刀仓坐标（**XY 必须，Z 可选**） | `[KNIFE:OK]` / `[ERROR:XY,EXC]` | 设置刀仓 | **由 SAVE_XY 升级，补 Z** |
| `$KNIFE_NEW=#6` | 登记当前主轴刀具编号（手动装刀后确认） | `[KNIFE:NEW=#6]` | 设置刀仓/手动 | 原样 |
| `$KNIFE_REPL=T2` | **换刀（按槽位 1-4）**：主轴有刀先放后取、无刀直接取 | `[KNIFE:REPL=T2:#5]` / `[ERROR:REPL=T2:#0]`（槽位无刀） | 执行换刀 | **参数语义修正：T=槽位，消除 #/# 歧义** |
| `$KNIFE_RELEASE` | 放刀：当前主轴刀具放回相应刀仓 | `[KNIFE:OK]` / `[ERROR:RELEASE]` | 执行换刀 | 原样 |
| `$KNIFE_PROBE` | **自动对刀（Z-Probe 取刀长偏移）**；换刀序列末尾固件自动执行 | `[KNIFE:OK,OFFSET=Z-0.32]` | 执行换刀 | **新增** |
| `$KNIFE_SETTER=X100Y10Z-50` | **配置对刀块绝对坐标**（+ 探针偏移/触发高度可选字段） | `[KNIFE:OK]` | 设置刀仓 | **新增** |
| `$KNIFE_STATUS` | 查询换刀状态 | `[KNIFE:IDLE,CURRENT=#6]` / `[KNIFE:RUNNING,TARGET=#2]` / `[ERROR:STATUS]` | 换刀 | 原样 |
| `$KNIFE_ABORT` | 中止换刀 | `[KNIFE:OK]` | 换刀 | 原样 |

> 备注：T=刀仓编号（1~4）；#=刀具编号（全局统一，**#0=空仓**）。**换刀参数统一用 T（槽位）**，
> 上位机负责"逻辑刀号 → 槽位"寻址（上位机持有刀库映射，最清楚目标刀在哪个仓）。

## 3. 安全底线（C1/C2，最高优先级）

### 3.1 "执行换刀不检测"的准确含义

- ✅ **免除**：刀具**种类识别**（哪把刀由设置刀仓时的登记决定）+ 用户干预；
- ❌ **绝不免除**：**仓位限位校验**（有刀/无刀）。登记是"人写的记录"，限位是"传感器的实时事实"，
  换刀动作只信传感器，不能只信记录。

### 3.2 固件内置的换刀安全序列（每次 REPL/RELEASE 强制）

```
放刀动作下探前：实时读目标槽 LIMIT
    → 该槽登记"空"但 LIMIT==1（有人塞了刀）→ 立即 E-STOP（急停+报警），绝不硬砸
取刀动作前：实时读目标槽 LIMIT
    → 该槽登记"有刀"但 LIMIT==0（刀被拿走）→ 报警/暂停，提示用户确认
```

- 该检查**由固件在动作内部执行**，不依赖上位机流程（上位机断连/App 被杀不影响安全）；
- 对应流程图"检查放刀仓位限位触发情况"节点：位置从"上位机雕刻流程步骤"改为"固件换刀动作前置"。

## 4. 换刀序列（固件状态机，含 C7 自动对刀）

```
$KNIFE_REPL=T2 触发
  ├─ ① 限位自检：放刀位(当前刀仓) 应无刀？取刀位(T2) 应有刀？任一异常 → E-STOP/alarm
  ├─ ② 放旧刀（读当前刀坐标 → 下探 → 放 → 限位确认）
  ├─ ③ 取新刀（读 T2 坐标 → 下探 → 取 → 限位确认）
  ├─ ④ 自动对刀（$KNIFE_PROBE：移动到对刀块 → 下探 → 记录 Z 偏移）
  ├─ ⑤ 更新 CURRENT/仓位到存储（$KNIFE_INFO 可查）
  └─ 完成 → [KNIFE:REPL=T2:#5]（成功）/ [ERROR:...]（失败，进入 alarm，见 §5.4）
```

## 6. 加工中换刀触发：两种模式（C10 修正外部 AI 的一处偏向）

外部 AI 建议"遇到换刀代码，上位机直接发 $KNIFE_CHANGE=T2"——这在**上位机主导（v2.1 模型）**下成立，
但与我们"高级功能归固件 + G-code 落盘本地执行"的架构不完全一致。**按路径区分**：

| 模式 | 场景 | 换刀触发者 | 说明 |
|------|------|-----------|------|
| **A 固件自主（推荐/默认）** | 路径二：G-code 落盘本地执行 | **固件**：本地解析换刀 M 代码，内部执行 `$KNIFE_REPL` 序列（含限位/对刀） | 符合"高级功能归固件"；上位机只发 startJob + 监听状态 |
| **B 上位机主导** | 路径一：上位机（网页/网关）逐段下发 | **上位机**：分段下发 G-code，遇到换刀代码主动发 `$KNIFE_REPL=T2` | v2.1 延续；指令仍复用同一套，只是触发者不同 |

> 两种模式共用同一套 `$KNIFE_*` 指令语义，只是"谁在换刀点发出 REPL"不同。固件侧实现无需区分来源。

## 7. 上位机"设置刀仓阶段"理想工作流（整合 C6，外部 AI 总结 + 我方修正）

```
① 同步：$KNIFE_INFO → 上位机获得当前刀库（逻辑登记）
② 需求：解析任务/G-code → 需用 #1、#5 两把刀 → 对照刀库缺 #5
③ 分配：界面提示用户"将 #5 放入 T2 槽" → 用户装刀 → 上位机发 $KNIFE_SET=T2:#5
④ 物理核对（安全前置）：$KNIFE_GET=T2 → LIMIT==1（确实放好）？不一致 → 弹窗警告"T2 设置了刀具但未检测到实物"
⑤ 存坐标：$KNIFE_SAVE_POS=T2:X900Y500Z-15
⑥ 复核：$KNIFE_INFO 全量确认 → 回主界面
开始加工 → 换刀点（A 模式固件自主 / B 模式上位机发 $KNIFE_REPL=T2）→ 固件执行限位自检+放旧+取新+对刀
```

## 8. 结论

- **大方向成立**（两轮评审一致）：检测/登记前置设置刀仓阶段、执行换刀按登记动作——逻辑闭环；
- **必须守住的安全红线**：仓位限位校验留在固件换刀动作内（放刀位被占 → E-STOP），
  "不检测" ≠ "盲放"；
- **指令集经 4 处修正/补充后对上位机完全够用**：REPL 按槽位、SAVE_POS 带 Z、新增 PROBE/SETTER、
  #0 清空语义、编号表落协议；
- **待你们拍板**：①限位 E-STOP 方案确认 ②REPL 按槽位是否采纳（vs 保留刀号参数）③对刀块坐标由
  谁提供（嵌入式硬件参数）④加工中换刀模式 A/B 各端责任 ⑤编号表归属；
- 拍板后：`$KNIFE_*` 正式并入 PROTOCOL.md（§2.9 ATC 指令集 + 附录刀具编号字典 + 换刀状态机）。
